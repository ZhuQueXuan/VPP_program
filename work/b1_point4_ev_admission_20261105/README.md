## 下一轮最少要取得的同场字段

| 记录 | 连接键与最低信息 |
| --- | --- |
| 任务、资格与实际分配 | `task_id × resource_id`，资源是稳定的匿名车、账号或可定义的桩。保留站点、同产品任务窗和请求 kW、报价前全体合资格对象、原分配组、区组/簇/序列与概率、分配依据和版本。无会话的人仍在名单里。 |
| 事前报价和车辆条件 | 同键加 `offer_version`；实际金额、币种、每次/每适用 kWh 的结算规则、适用窗、通知/送达时刻。同步保存截止前的需求 kWh、计划离站、SOC 或可用代理、初始功率和设备上限，并留字段可用时间。 |
| 执行、计量和基准 | 同键加会话或设备映射；接受/拒绝/未知、调用和回执状态及时间，原 UTC 表计点/区间、单位、质量、设备覆盖及退组。30分钟物理结果另需有依据的未调节功率轨迹和版本。参与率另需全体受邀及接受/拒绝日志。 |

收到新原件后，先按联合键核跨表连接、时钟和每臂分母，手算一个原始窗口，再冻结比较。首个基线采用原分配的两组均值差，按真实分配单位报告不确定范围。覆盖完整的零、确证未交付的零和缺测分别记账。若只有可信分配和同窗实测 kWh，优先回答固定方案的组用电差；若补齐参照和车辆事前条件，再做半小时累计有效减载秒数及净减载电量。先比较实际报价，不由有限档位外推连续曲线。总管复核后决定是否打开效果数据。

新资料优先追两件事：Optimise Prime 能否核清 B 计划的字段语义，并补同类场站日期的出价、出清、未中标及覆盖记录；Calgary 若有授权途径取得原件，能否恢复全部分配车辆的家庭充电覆盖。Calgary 维持原访问记录，暂不重试。两条线分别按场站任务和车辆充电移时报告。
