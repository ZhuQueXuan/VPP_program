# 趋势滤波失效诊断与改进建议

2026-10-31。按用户要求先分析第一部分，正式报告后置。原pilot已见4块数据只用于诊断，未重训参考、未选新参数或改变原方案；进行了明确标记的真实参考/去噪和固定Σ×λ受控重算，不生成新事实，不冒充新独立测试。

## 1. 结论与优先级

**参考预测的持续正负偏差，是当前误检和大幅时长错判的重要上游原因；现有完整协方差趋势滤波又没有把这些偏差当作背景分离，并在弱信号上保留更多零散越阈格。任务证据还存在小校准集的不稳定与得分尺度不匹配。三者相互影响，不能用一个原因包办或分摊百分比。**

下一步建议先处理合法事前信息下的参考有符号误差，再修任务证据的长度归一与保证口径；暂停继续把完整Σ加权当默认改进。全过程特征的主目标应是累计/连续时长及其可信度，不能用“整次不再报零”代替完整持续时间正确。

具体不应先做：统一减参考常数、继续增λ、抬物理阈值、只增加GP/网络复杂度，或直接采用CPOP替换主线。已见test不得再选新配置。当前没有新的正式算法选型。

## 2. 少漏为什么仍会时长很差

当前“整次漏检”只要求拟合后任务窗内没有任何格达到.15kW。一条真实20分钟响应，只识别出1分钟，就不再算整次漏检，却仍少了19分钟。

全量176条真实阈上弱响应中，GLS整次漏只有1条，但72条仅被缩短，单是这些缩短就产生24720秒绝对误差；全漏那1条只产生120秒。GLS漏算真阈上格437个，反而多于CP原计量σ的408个。

最突出的是低幅持续组：48条，峰值.14q=.21kW，GLS没有整次全漏，时长MAE仍423.75秒；CP同组402.50秒。其峰值距离有效阈值.15仅.06kW，缓升/波动的部分格更接近阈值，参考负偏和噪声都足以压掉很多有效格。

每个任务严格有：

`时长偏差 = 60×(多算阈上格 − 漏算阈上格)`。

总时长还会抵消位置错误。GLS有7个真实阳性任务多算/漏算格数相同，时长恰好正确但时段错位。因此下一轮应同时看漏算分钟、多算分钟和时段位置，整次漏检只作辅助指标。

这不是“所有响应被拉长”。当前弱响应大部分主要损失是缩短；无动作正偏则表现为多报时长。全量分层及计数恒等式见[参考与特征诊断](reference_error_analysis.md)。

## 3. 参考还是提取：两组受控证据

### 3.1 参考误差确实是重要瓶颈

全量null256任务中，GLS误检24条、CP原计量σ误检6条，6条全部共同。GLS的24条中23条在拟合前的原始参考差残差就已经有格越阈，并非24条都由滤波凭空制造。

共同6条任务平均参考偏差约+.133kW；GLS独增18条约+.085kW，且18条均为正偏。全体任务参考均偏却为−.015kW，同时存在负尾，故不能统一把所有参考下调一个常数。

为区别相关和输入原因，固定每块前8用户×2事件，取64基础任务、强/弱/null共192配对变体，不按误差选；保持原Σ、λ和CP计量σ=.05，只改变输入参考/噪声。

| 固定子样本的输入 | GLS弱时长MAE | CP弱时长MAE | GLS null误检/64 | CP null误检/64 |
|---|---:|---:|---:|---:|
| 原预测参考，原噪声 | 182.81秒 | 148.13秒 | 10 | 5 |
| 换真实参考，原噪声保留 | 63.75秒 | 45.94秒 | 0 | 0 |
| 真实参考，再去计量噪声 | 1.88秒 | 30.00秒 | 0 | 0 |

同一受控子样本，GLS强场景MAE也从57.19降到5.63，再到0秒。只换参考、保留原噪声已明显改变错误，支持优先解决参考误差；干净输入下TF能工作，不应把它判成完全不能表示响应。

但真实参考不可部署；这些数字不是新测试或可达到性能保证。原误差模型在oracle条件下仍保持冻结，三种误差有交互，不能用MAE相减报告“参考占多少%”。oracle无噪下TF优于CP也不能作为采用理由。详见[oracle结果](oracle_diagnosis.json)、[独立重算](oracle_independent_check.md)。

### 3.2 提取目标与相关权重也有独立问题

在同192变体上，另固定参考、事实和物理阈值，只交叉改变scalar/diag/full/trace-normalized full四种Σ与λ2/4，不选择新赢家。

同λ2、同每格对角方差，完整Σ相对对角Σ使弱整次漏检3→0，但弱MAE176.25→182.81秒，null误检8→10/64。所谓救回的3条真实时长1200/300/300秒，完整Σ都只测出60秒。漏算真阈上格总数仅120→119，假阈上格却74→84。

λ4下也有同方向反例；完整Σ共同尺度只比scalar差约6.56%，做trace归一结果几乎不变，不能把主要差异都归给平均方差尺度。另一方面，full下λ2→4的null误检反而10→11，不能保证加平滑就单调减少阈值误检。

更根本的是，当前TF只惩罚二阶差分。常数和直线的二阶差分为零：若输入本来是一个持续正偏，原样输出的拟合损失和惩罚都为零，增大λ也不会自动去除它。**协方差加权告诉算法哪些误差方向较常见，却没有额外信息证明某个持续正残差是背景偏差还是实际响应。** 本轮16个构造控及所有解的加权矩条件核过。

因此，问题不是只差一个更大λ或数值求解没收敛。相关权重在当前目标下改变了近阈值片段的保留，没有改善完整时长；是否因Σ估计不准还是目标不适配，尚未完全分离。无真实回补的null也有同样问题，不能把额外误检全归于回补边缘振铃。[固定交叉诊断](factorial_diagnosis.md)

## 4. 整任务5%为什么没有在这次留出达到

### 4.1 两个判定目标不同

开发λ的5%门限针对“是否出现≥.15kW的正时长”；校准rank针对“扫描得分是否异常偏正”，不要求达到.15。CP共同总σ在null只有3/128用户出现正时长，却有11/128用户被判有证据，其中8用户没有任何正时长。不是漏除事件数的代码错误。

当前得分为窗口残差和/√长度。理想例子：持续30分钟+.10kW偏差得分约.548，已超过GLS校准阈值.538；而3分钟.21kW真实弱矩形的得分只有.364，3分钟.30kW也约.520。**持续的小参考偏差，可能比更短的真实弱响应更容易触发。** 这些是公式示例，不是新增模拟性能结果。

### 4.2 边际5%不保证冻结后这个阈值的风险≤5%

rank和两任务用户最大值实现正确。48校准用户时，p≤.05等价于超过校准第二大分数，尾界实际只靠少量用户决定。理想连续同分布独立用户块下，这个阈值的真实上尾概率随重抽校准集服从Beta(2,47)：均值约4.08%，95%分位约9.51%。

在同一理想模型中，128个新用户出现至少12/11/13个误报的概率约8.5%/11.2%/6.4%。它说明这次9%—10%不自动证明秩方法数学错误；也绝不证明这个固定阈值已经可靠。5000次冻结分数的用户块置换只是同一事实的诊断，不增加样本或产生新校准器。[条件有效性原文](https://proceedings.mlr.press/v25/vovk12.html)

当前用户块误报实测TF12/128、CP总σ11/128、CP计量σ13/128，均高于目标，应如实保留。该方法在用户块可交换等条件下提供的是对校准抽样平均的边际口径；本pilot存在日历混合差异，不能直接认定这些条件成立。它不是对这一次固定校准阈值的条件误报风险≤5%的认证，更不是保证每一个小批次计数必≤5%。

### 4.3 共享参考尾部与采样设计也须处理

四种设置误报用户并集16、共同8，与参考正偏高度相关。cal任务参考均偏95分位约+.0800、test+.0955kW，test正尾更重，主体均值却仍偏负。

已发现一个确定设计缺口：用户索引与星期绑定，cal48用户有星期3/4，而每块test32用户不含这两组；整周平移保证时点合法，不能保证分布相同。但不能就此认定日历差异是超限主因：新增cal索引段的user38反而提供最高尾点，原第二大又恰好等于前32用户最大值。有限尾样本波动与分布混合尚不能从这次数据完全分离。[校准诊断](calibration_diagnosis.md)

## 5. 有依据的最小改进方案

**推荐顺序：先处理参考的有符号持续偏差，再修任务证据尺度；点特征和证据分别验收。** 不同时叠加新网络、完整Σ、新阈值和新阶段模型。

### 第一步：只改可合法预测的参考偏差

保留当前参考作内部起点，利用独立已完成non_event，做一次低复杂度的条件参考校正。可复用已有通知前前缀×horizon正则模型，或在相同信息下拟合简单状态/残差模型；优先利用已经具备的完整通知前轨迹及历史，核近期水平、趋势与未来horizon的关系，不先扩网络。

具体可设参考误差均值为m(X,h)，用训练用户外预测的non_event残差（预测−实际未调用功率）学习；新参考为原预测−m。X只能是通知前信息，不能以本次任务后的均值估m。这样既可能修正正偏，也可能修正负偏；统一下调只会把误检换成弱时长缩水。

内部选择除MSE外，检查不同持续长度下的正/负误差尾、条件偏差和稳定性。校正收益先归参考，不称新过程算法。已有模型是可复用候选，不能把再接一次旧模块当创新；本轮未实现/验证这种校正。

### 第二步：让时长目标和可靠性输出明确

暂停把完整Σ当作已证明有效的点特征改进。下一小验证先固定简单可核的过程底座，对角/结构化误差与完整Σ只做必要内部消融，不按本test直接改正式默认。主要指标用累计/连续时长、漏算/多算分钟、位置错配与幅度；整次至少一格检出降为辅助。

低频背景与真实持续减载可能相同，禁止自由拟合任务内偏置后从响应中扣掉。不能只给曲率惩罚加λ指望自动分离。难区分时保留点值及不确定状态；如果研究特征范围，可用独立非事件的整段误差约束给“确定越阈/可能越阈”的时长上下界，先检验覆盖与宽度，不冒称完整置信区间，更不能把证据不足置零或删掉。

这一步没有预承诺哪种提取器会赢。真实参考诊断说明TF在干净输入能工作，但同噪声下仍有弱时长反例，必须用下一轮新独立数据重新判断。

### 第三步：只加一个任务证据机制

把当前单纯sum/√长度，改为按扫描长度的背景误差中心/尺度归一。例如在独立dev非事件拟合后的曲线上估每个长度L的窗口和中心与波动，再把各长度标准化得分取最大；相关误差的尺度由数据估计，不假定所有长度都按独立噪声√L增长。条件化只用合法事前条件且保持低复杂度。

所有长度/窗口搜索一起交给全新的独立用户最大值校准，不能每个窗口挑到显著为止。此机制针对“长小偏差压过短弱信号”的效率问题，不改变物理.15kW判据，也不会自动改善原始点时长。与第一步参考校正分开验证，避免将任务判定改善算作时长算法改善。

### 第四步：先定清5%的含义，再定有限校准预算

建议将未来要求写为“冻结后同分布用户块的真实误报概率≤5%，以95%校准置信度支持”，同时报告弱功效；这是建议口径，非当前已经实现的保证。

在连续iid且取第r大校准分数的理想模型下，可用精确容忍界选n/r。48用户即使用最大值也不足以给95%/5%；取第二大需至少93独立用户，96用户时其风险95%上界约4.85%。**96用户/r2与直接把n加到96仍用标准α.05的第4大不同**，后者上界约7.88%。这些是理论设计下限，不保证分布变化或弱功效；不能只扩大样本数就宣布完成。

采样同时解除用户数量与日历范围的捆绑，以相同事前人群/日历规则生成或抽取cal/test。不要在当前已见test删困难用户/星期。更保守尾界可能牺牲弱响应，必须与得分归一、弱证据不足和时长范围宽度一并评价。

## 6. 怎样比较、成功及停止

仍按两板块组织，当前只做第一部分，最终正式比较保留一个CPOP算法对照（原计量设置保留），所有方法共享相同合法参考/任务/资料/校准协议。参考校正、误差权重、得分归一仅用有限内部消融解释来源，不重开每模块baseline项目。第二部分不动。

下一轮应先预定一次开发/验证/新测试，先改参考并固定过程验证，再独立研究score；不在这256基础任务上选模型。成功必须同时看：

- 低幅持续响应的漏算分钟及完整时长MAE下降，不只整次漏检减少。
- 无动作原始时长误检不因弱响应检出改善而明显增加；强响应/恢复结果和可用率受保护。
- 整任务用户块风险按选定边际/PAC口径、支持条件与独立数据评价；不只报事件率。
- 不通过增大拒答/不确定、阈值或删困难样本制造优势，所有数值与不确定状态保留。

若只有参考收益，就按参考收益收口；若只有证据效率改善，就不称点特征更准；任一候选一次独立验证无实用增量则停，不继续追本test。
