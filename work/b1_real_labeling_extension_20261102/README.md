# 真实开发片段第二批核验与训练输入整理

本轮把开发片段初审从64个扩充到128个，并整理了按原用户分组的开发训练输入。没有训练或更换生产模型，没有读取封存测试的观测，也没有形成新的真实准确率。

正式入口为 `data/ACN_real_user_benchmark_v1_20261102/ANNOTATION_STATUS.md`。本批新增标注在 `annotations/batch_20261102_b/`；可读入的开发输入在 `prepared/observed_localization_pilot_v1_20261102/`。旧标注、旧选择及旧凭证保留。

## 实际完成

新增64个窗口来自63个匿名用户，其中54个用户未在首批出现。两批共128个窗口、118个用户；训练96窗/96用户，验证32窗/22用户，用户跨组为零。同一会话的新旧窗口不重叠，不能把重复用户计成独立车辆。

收到上限短暂变化、小幅变化、其他阶跃、上限不变各新增16窗。`protocol.json`在新一批看图前固定数量和选法；`selection_freeze.json`先冻结选择，再查看 `review_pages/page_17.png`至`page_32.png`全部16页原始图，并回查关键行。选取依赖收到上限历史、时间与用户哈希，不依赖功率是否响应、算法输出或模型分数。没有挑出“容易判”的片段冒充整体真实效果。

本批整窗39个可辨认变化、23个无清楚独立事件、2个未解决。锚点附近另标23个可见跟随、16个无明显跟随、9个未解决、16个无上限边沿。两种标签分开：晚发生的停充不能冒充当前指令跟随，恒上限也不能自动当无变化。以上只是分层开发片段计数，不是现场类比例或算法成绩。

新增22个可辨认起变范围、10个恢复完成范围；合计50个和29个。Case 80有明显短下降，但首次小变化与下一格清楚变化之间难定起点，保留正的存在判断、起变字段为空，没有为了整齐硬给一个边界。所有不明目标都保留为空，不变成负例。

## 影响训练的发现

- Case 125：低上限只保持3秒，实际电流经多个原始点爬升，15秒才回到此前水平。Case 94：低上限9秒后，实际仍经历较长渐进恢复。不能以指令保持时间直接造有效响应时长标签。
- Case 87：第一个上限保持60秒，之后换为更高上限继续升高；“短上限”抽样类别并不代表短物理动作已经结束。
- Case 74：恒上限下实际停充；Case 75/90：上限变了但输出仍零。指令变化既不等于变化存在，也不提供完整起止真值。
- Case 98/103/108：上限整窗零而有实际输出，电压字段缺失。记录含义单独标记，不认定已知故障，不给干净负标签。原电流、功率、状态和电量都保留。
- Case 123：包含125A上限以及短时间内很密集的零/非零往返。官方元数据能对应同一会话，但没有在本轮认证硬件类型；单列高上限/时间戳密集的上下文，不能混称已经确认的普通AC短响应或故障。

额外对首批64份开发原件读取电压、充电状态、累计电量，结果在 `channel_audit.json`。不同设备的可用字段不同，同一桩电流/功率/电量不能充当三个独立故障测量。原记录有的功率与电流电压乘积不同，不能仅凭差值推断故障或自行修值。

源含义依据包括[公开镜像说明](https://github.com/tongxin-li/ACN-Data-Static)、[ACN官方字段说明](https://ev.caltech.edu/dataset.html)和[作者论文](https://thesis.library.caltech.edu/14191/1/Lee_Zachary_J_2021_Thesis.pdf)关于不同设备字段支持的说明。本轮只取得后者网页检索文本，全文工具访问超时，命令行公开下载也失败，未冒称拿到全文或完成硬件逐桩认证。失败状态留在 `source_documents/source_receipt.json`。

## 已整理的开发输入

`prepared/observed_localization_pilot_v1_20261102/training.json` 与 `validation.json` 可直接由后续开发实验读入。每条保留原始非等间隔时间、电流、收到上限和功率；原始点不删、不插值、不补缺口。注册表另存用户/会话/源文件与行号，模型输入不混入用户身份、站点身份、人工解释或标签。

目标分别为整窗可见变化、锚点可见跟随、可辨认起变及恢复完成的原始范围。它们仍是**单助手初审的暂定观测标签**，不是独立人工金标准或干净物理真值。另一个审阅者的复核尚未发生；已生成不带首审答案和模型预测的Label Studio复核包，本批补充了原始电压、电量和源状态上下文。没有安装服务，也未验证实际服务导入。

开发输入的计数：训练有40个可见锚点跟随、22个无明显跟随，34个不适用/未解决；验证为11、7、14。起变位置训练39个、验证11个。数量仅适合先诊断真实定位方法的可行性，不能据此宣称完成大规模监督训练。任何后续探索性拟合必须明确使用暂定观测监督；正式准确率、物理有效时长和故障精度仍不能据这些标签认证。

恢复完成不是旧0.15kW有效阈值的结束；本轮仍没有有效时长、无噪功率、故障或控制成功的监督目标。没有把两个边界相减伪造这些标签，也未将未知反事实参考预测重新引入研究主线。

## 核验

`verify.py`重新读64份新开发原件，核对20005个原始数值、4001个源状态、32个相邻采样边界及20个显式电平描述范围。新边界间隔1至6秒，中位4秒；这不是物理定位精度或置信区间。

同时核对1878份原件的字节哈希、13份旧采集文件、6份旧标注冻结文件、38份旧工作/数据文件及58份生产算法文件，均保持不变。封存测试只做字节校验，不解析观测值。`verification.json`保存读入源路径、分组和逐项数量。
