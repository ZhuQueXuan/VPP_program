# 第2点伦敦电表联接审查与收口条件

2026-11-04。**小样本联接通过，可以进入正式比较的设计和数据准备。当前样本和分配证据不足以直接计算正式效果。**

## 审查结果

- 首选的两个官方分片全部为标准费率。保留该失败后，用匿名 ID 定位线索在同一官方 ZIP 定向取第165片的前缀，收到的字节范围共 12 MiB。定向探查依据组别和覆盖时间选两户，保留前缀末尾及无法整成员校验的边界。前两完整分片通过 CRC，定向前缀以同版本范围及内容散列核对。[取数凭证](targeted_access.json)
- 主审从官方压缩前缀复解并核对散列、770条唯一原始电表行、840行联接台账的电表与费率源行。六个预选时段高、低、常价各 24/24 个半小时有值，六个全试验日各档 192/192。普通日这两户无原始零或缺测，不能推及全库。秋季换钟日两户各有一个同值重复键，单列保留。完整时段的原始零、空值、Null、缺行、重复键、切片范围外须分别记账，缺失不置零。事件窗属于试验日，两份计数不能相加作独立样本。[分母](targeted_link/denominators.csv) · [联接台账](targeted_link/linked_intervals.csv)
- 采用费率本地起点与电表 GMT 期末的连接口径有同源作者的标准组说明、UKDS 动态组另一版本的说明，以及样本换钟键的支持。两个住户的时间键能对上，仍欠该公开版动态电表的期末和事件类型直接对照。两份旁证及冬夏样本可支持继续准备比较，不能靠比较结果好坏选择时间偏移。[同源作者说明](https://research.tudelft.nl/en/datasets/low-carbon-london-smart-meter-data-refactored/) · [UKDS 指南](https://doc.ukdataservice.ac.uk/doc/7857/mrdoc/pdf/7857_userguide.pdf)
- 逐次合资格、通知送达、接受与拒绝仍无可用记录。动态组名单和用电记录可用于用电研究，参与作为独立待补证据。[交付报告](README.md)

## 第2点的收口安排

技术执行环节保留已复核的 CrowdCharge 两张实测表。报价环节只推进一项核心验证，比较动态组内相近条件的高、低、常价窗口的实际 kWh，同时检查全天 kWh 以辨认移时。先锁定普通工作日三小时同类时段、节假日、季节、邻日与缺测处理，确定能区分有实际意义差异所需的日期数。住户能改善事件日均值的精度，独立分配的信息量按事件日期及排期依赖核算。实际事件标签或日期分配依据不足时，只报告可支持的条件差和范围，不能把同源自选的标准组当随机对照。

正式比较的放行条件是时钟与事件标签可追溯、有足够可比事件日、完整的目标住户分母，以及预先固定的统计方案和不确定性报告。先做一次必要的方案与覆盖审查。满足条件后做一次简单正式比较，结论允许差异接近零。关键条件仍不可得时，收束伦敦路线，记明具体缺口，不再反复换模型或扩展相邻小任务。届时把主力投入第3点的时序资料与盲核可行性。第2点按有证据的范围阶段收口，逐次参与、恢复和跨资源证据不足仍列在总框架中。

本轮交付是联接核验，未计算报价效果。正式分组比较预期不需模型训练或远程服务器。若后续出现明确的训练任务，再按比较基线、数据版本和可验证的提升目标说明服务器需求。
