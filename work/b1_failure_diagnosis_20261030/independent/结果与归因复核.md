# RIDE与CPOP失效原因：独立结果复核

2026-10-30。只读复核本轮 `run.py/protocol.json/diagnostic_metrics.csv/summary.json/summary.csv/optimization_probes.json/positive_controls.json`，并独立重算分组指标、真值见证与旧文件身份。正式源码、原始事实、旧实验结果均未改。

**结论：根代理提出的有限归因成立，应优先修查当前模板的后窗拟合和局部搜索；现在没有充分依据直接放弃模板，也没有证据证明任何新方法已超过原CPOP。** 参考误差与模板实现是两件同时存在的问题，不能各分摊一个可加百分比。

## 1. 数值结论核对

诊断为已见数据中的8个块，每块16用户两事件；正/零机制各256记录，共512配对事实变体。所有条件保持同批事件、q、阈值、窗口与名义sigma；清洁输入仍固定sigma0.05，不同时改变BIC/惩罚尺度。root汇总与逐行指标一致。

| 正作用同256事件，累计时长MAE/秒 | 当前RIDE | 原CPOP |
|---|---:|---:|
| 所选预测参考+计量噪声 | 271.88 | 100.08 |
| 真实参考+同一计量噪声 | 269.30 | 7.73 |
| 真实参考+无噪声 | 225.00 | 3.05 |
| 清洁输入，仅取消后窗回补 | 1.17 | 1.41 |
| 清洁输入，仅放松RIDE回补上界 | 234.14 | 3.05 |

这些差值表示固定实现对条件变化的敏感性。预测参考换成真参考后，CPOP时长误差明显降低，RIDE仍很大，排除了“只要参考预测好就能解决当前RIDE差距”的解释。两法真无动作误检在oracle参考诊断中均为0，支持参考误差是这批误检的重要来源；模拟噪声有界且幅度低于任务阈值，不能推广成真实误检保证。

取消后窗回补后，RIDE任务内时长误差降至约1秒；只放松幅度界后，后窗曲线误差大幅降低，但任务内时长误差仍高。说明当前任务内损失高度关联后窗拟合，单独放宽回补幅度不足以解决。零作用配对有相同方向的后窗影响，不是正作用曲线专有现象。

## 2. 表达能力、模型选择与数值搜索必须分开

M1不能独立安排释放后空档再回补。M2可用唯一掉落段表示末端空档，因此不能说整体模板绝对不能表达该过程。

根代理选取15个真实参加的near_step例，按预定类型与事件顺序取样，不按拟合误差挑例。在oracle/无噪/合法放宽幅度界下，每例都构造出一个满足参数界的M2见证，逐格拟合原真值误差小于1e-10，RSS约1e-27。该见证用于证明存在一个更好的合法解，未作为实际算法输入。

但默认起点下，12/15例的M2目标劣于这个已知可行解；固定增加至至少12起点后仍11/15。默认参数n_starts=3只是下限，已有启发式初值一般超过3个，不能简称“仅3次优化”。这证明当前局部搜索并未可靠找到模板内的好解，纯增加少量随机起点也没有解决。

更强的正控是：在完全属于原M2、回补幅度也在原界内的清洁“末端空档再回补”曲线上，RIDE选M1且时长误差600秒，原CPOP为0。此时M2精确解的BIC约36.85，而所选M1的残差使其BIC大得多，因此不能把失败归为“BIC合理地偏好简单模型”。该场景的直接证据是M2分支优化不充分，随后结构选择消费了这个差的拟合值。

这不证明所有响应形状的误差都能用求解修复。间断再加末端空档可能需要两个独立缺口；非线性爬升/疲劳也不完全属于现模板，仍有表达近似与指标敏感性问题。局部搜索改好后才能公平量化这些剩余损失。

## 3. 配置域与参考问题

默认模板回补上界为q=1.5kW，模拟回补速率为1.8kW。独立审计原主面板发现，正作用2205/2205、零作用1463/1463真实响应事件均有后窗计量格越过该界。因此旧结果系统性包含配置域不匹配，不能直接据此否定参数模板方法本身。

参考不确定性缺口也真实存在：现适配器的sB=0、lr_crit=None，没有把参考偏差纳入标定后的判别。sB只影响LR/区间，现BIC分支不读它，单改这个值无法修复当前点估计。参考偏差与响应识别的可分性需要单独的实际机制、合法历史校准和失效保护。

## 4. 建议给用户的决定选项

**优先的低成本选项：先做一轮有边界的模板求解修复候选。** 针对末端空档的有效参数化/确定性初值、模型分支搜索与终止诊断，另明确合法回补幅度。先要求上述已知可表达正控稳定通过，再做未见数据上的过程/误检/作用比较。它有明确已定位故障，不需要立刻推翻整条主线。

**备选研究路线：以CPOP为通用核心建立真正增量。** 适用于修复后模板仍难应对的未知/多段形状；增量可以来自明确的参考误差处理、任务边界与约束、或有校准的阈值/检测。每项新增机制都需同信息消融、原CPOP对照、预定指标和新独立验证。仅换成原CPOP没有相对改进证据。

当前诊断足以排定修查优先级，尚不足以决定最终替换、证明哪个新候选优于原CPOP、或验证正式数据效果。正式报告与后续功能本轮继续后置，由用户基于诊断决定下一候选。
