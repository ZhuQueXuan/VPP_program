# CPOP改进失败原因与下一方向：仅分析

2026-10-31。用户要求分析上一版真实短响应漏检、查相关论文、提出更合适方向；只第一部分，原CPOP/LABS保留，报告后置。本次无新算法、优化器、预测训练、新实验或参数选择。只读已有事实/真值/曲线/权重/原生目标值。

## 1. 三条漏检直接来自新增降权规则

常规高斯条件的24条模拟真实单格响应，原CP0漏，候选κ5多漏3条。它们分别发生在任务第6、14、21分钟附近，不在指令切换保护区；真实减载约.75—1.06kW，明显高于.15kW判据，不是原本就没有足够幅度。

| 任务中观测减载/kW | 降权后保留的平方误差权重 | 原CP峰值/kW | 候选峰值/kW |
|---:|---:|---:|---:|
| .9983 | 5.94% | .9983 | .0112 |
| .9159 | 7.11% | .9159 | .0115 |
| .8083 | 8.90% | .8083 | .0074 |

邻近点接近零，被当作孤立异常；局部权重压到原来的6%—9%后，保留响应的证据变弱，额外折点惩罚没有同步变，最终选择0折点的平缓曲线。逐条重算目标与保存的原生目标值一致：在新权重下平缓曲线更便宜，但按原权重评价则不是。求解器正确求解了被我们改错的目标，不是收敛故障。

指令的发送时点不等于用户实际响应时点，保护指令边沿不能自动保护任务中段的短动作。同一条单格曲线可能由真实短动作或测量异常产生；本规则没有独立信息区别二者。仅给它附上“歧义”标签，也不能补救点估计已经被压低的后果。

逐条输入、权重、拟合及目标分数见[diagnosis.json](diagnosis.json)，复核脚本[analyze.py](analyze.py)。这些是旧测试的机制诊断，不增加性能样本数，不据此调κ。

## 2. 原CPOP目前主要卡在哪里

当前已知参照比较没有预测器，所以此次问题不归参考预测。

1. **异常噪声下会追随大偏差。** 原CP时长综合误差从常规22.25s增至加尖峰55.625s。低幅持续组最长连续误差从47.5s增至392.5s，说明尖峰会打断/扰乱近阈值的连续时长。实际有多少是尖峰自身/邻格拟合变化，需要结合逐事件，不能把全部误差等同某个单点来源比例。
2. **曲线拟合目标与时长目标不同。** 常规间断组累计时长MAE27.5s，最长连续MAE120s；少量关键格的阈值归属变化就可能改变整段最长时长。减小曲线RMSE不保证时长或阶段更准。
3. **斜坡、平台和突跳的表达值得核查。** 原CPOP拟合连续折线，而任务可能含突然退出/恢复；这是一项合理模型扩展假设。目前未用结构消融证明它是本次误差主因，尤其不能拿它解释新增3条漏检——原CP对这24条本来就能识别。

当前不能笼统称“CPOP识别不了短响应”，也不能因为局部正结果继续加大平滑、最短段长或异常压制。

## 3. 文献支持与取舍

- **Fearnhead与Grose，JSS2024，CPOP软件论文**：§4.4明确指出最短分段长度能降低重尾/点异常过拟合，但会漏掉比该长度更短的真实变化；§4.5说明默认惩罚依赖iid高斯已知方差假设，并已有CROPS范围选参。故最短段长和CROPS不是本项目新方法，也不是本问题无代价的修复。[原文](https://www.jstatsoft.org/article/view/v109i07)、[全文](https://www.jstatsoft.org/article/download/v109i07/4577)。
- **Fearnhead与Rigaill，JASA2019，R-FPOP**：§2.1及模拟也保留真实短段被稳健损失解释成异常的风险。文中有联合拟合优于特定预处理方案的实验例子，但不能保证解决单点真动作/故障的不可识别；常均值模型也不能直接冒充连续变坡CPOP。[作者预印本](https://arxiv.org/html/1609.07363v2)、[作者代码](https://github.com/guillemr/robust-fpop)。
- **Kim、Oh与Cho，Technometrics2024，MOSUM线性模型**：用多个窗口比较局部线性参数，允许水平跳变和斜率变化，支持“把真实短段/跳变保留为候选”的思路。理论需要间隔/窗口及噪声条件，不能保证单格可识别或当前5%可靠性。作者R/Rcpp代码公开，但本轮未核到明确软件许可，不直接复制或安装。[作者机构与接受稿](https://research-information.bris.ac.uk/en/publications/moving-sum-procedure-for-change-point-detection-under-piecewise-l/)、[作者仓库](https://github.com/Joonpyo-Kim/MovingSumLin)。
- **Grantham，GRACE，2026-09首发、10-12修订预印本**：将CPOP作为特例，允许平台、斜率改变及水平跳变等转移共同竞争。它为扩充段结构而非先压点提供新近理论思路；本轮未核到成熟可直接复用的作者软件或EV性能证据，不把理论框架当已证明更好的替换算法，不立即移植整套高维状态递推。[v2全文](https://arxiv.org/html/2609.28831v2)。

文献只提供改进依据，不作为新方法已胜原CP的证据。未运行网页代码或新增库。

## 4. 推荐的下一方向

建议下一版研究**保留短动作的整段过程识别**：保留原观测权重，先在CPOP基础上有限增加“缓慢爬坡/平台/突然变化”的段或转移候选，用整段证据比较，不在入口先把孤立点判成错误。多尺度只利用实际已有采样，不对1分钟数据补造秒级细节。

短动作与瞬时异常的区别，优先从现有更细采样、指令、设备状态或适用的多通道一致性寻找证据。若仍只有一个不可区分的分钟格，就保留两种解释和未决状态，不强制压零，也不靠提高最短段长排除它；不把不确定输出增多当作准确率提高。

下一轮若实施，应固定一个有限结构扩展，预先检查真短响应不多漏、真间断不被填平、低幅持续和最长时长改善、异常下不多误报及运行成本，再用全新验证/测试与原CP和LABS同条件比较。结构扩展只是待验证建议，不能预承诺取胜；不在本批旧test调惩罚或挑反例赢家。

本次不改算法/默认、旧数据/科学冻结、第二部分或报告；原CP作为基础和独立对照、LABS作为第二对照的路线保持。
