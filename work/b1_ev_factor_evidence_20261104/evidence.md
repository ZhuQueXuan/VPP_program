## 初始关系与证据等级

**文档**指已公开的制度或试验流程，**样本**指当前可以复算的事实或关联，**假设**指方向有业务依据但识别还需条件，**缺证据**指本地无同场对应字段。对有多重证据的关系分别标注。

| 方向与阶段 | 作用对象和预期方向 | 现有证据和可验证范围 |
| --- | --- | --- |
| 日前电价、预期站点占用、技术与预算约束 → 站点折扣安排 | **报价依据**。超市试点倾向在低价或光伏富余时段安排优惠，具体档位还受优化约束。 | **文档**，超市论文和项目说明。**样本**，可复算折扣—市场价—预测占用联合分布。**缺证据**，缺逐小时实际规则输入版本及发布时间，无法从已发布表重算每次决策。 |
| 任务时窗、所需削减与报价前可调状态 → 资格、报价与请求量 | **筛选及报价依据**。期限、需求或桩容量是否影响报价取决于运营规则。 | **假设**，项目业务设定。**缺证据**，ACN 无同任务报价或资格快照。仅在现场确实依据该状态定价且该状态影响结果时，才把它当报价与结果的共同原因。 |
| 时段、历史充电需求、到站环境 → 站点用电 | **站点使用与基线**。日历与历史可刻画自然充电差异，也可能参与折扣优化。 | **样本**，可按当地小时和日期做描述性比较。**假设**，当天促销、拥堵、邻时段折扣与代替站点可能共同影响结果。 |
| 事前报价、送达 → 接受、拒绝、无回执 | **参与**。奖励可能增加接受，方向与金额需按实际制度检验。 | **文档**，OptimizEV、CrowdFlex 的激励和选择流程。**缺证据**，本地没有同时具备报价和完整邀请状态的车辆事件。超市可检站点用电关联，无法得到用户接受率。 |
| 预计离站、剩余申报需求、SOC、车辆可用性 → 接受和开放能力 | **参与与承诺**。余量较大或需求较低可能允许更长调节，具体受用户偏好与车辆限制约束。 | **文档**，OptimizEV 明确期限和收费选单。**样本**，ACN 有两类事前代理。**假设**，需要报价前 SOC、充电能力和时刻，OptimizEV 使用实际电量与停留计算的事后余量只作描述。 |
| 接受、开放范围、当前接入与站点能力 → 调度下发 | **可调能力转成请求**。参与之后仍可能未被调用，设备不在线也可阻断指令。 | **文档**，CrowdFlex、OptimizEV 有调度步骤。**缺证据**，本地缺任务级授权、未调用原因和下发回执。 |
| 实际限额、原功率、设备与 SOC 状态 → 实测电流/功率与早退 | **执行**。限额压到原电流以下才更可能触发可见降幅，车辆或桩的状态可能让执行延迟或中断。 | **样本**，ACN 同会话可观察限额变动、跟随、无可见跟随。限额可能由调度根据已有负荷下发。**假设**，量化因果效应需可信的控制来源或外部指令变异。 |
| 指令解除、实际少充电量、剩余需求和可用时间 → 回升、回补与恢复 | **恢复**。解除限额提供回升条件，用户可能已离站、到达目标或受桩容量限制。 | **样本**，ACN 可观察回升及实际拔枪。**缺证据**，任务结束与参照缺失，回升、恢复完成和回补电量分别核。若观测在恢复前结束，保留截尾。 |
| 执行轨迹及参照 → 累计有效减载时长、减载电量；恢复轨迹及参照 → 恢复时间、回补电量 | **结果计算**。同一任务窗口内，以实际功率与批准参照的差计算结果。 | **文档**，会议纪要与项目框架规定。**缺证据**，ACN 的限额和实测功率无法单独确定参照。超市站点小时 kW 是不同结果。 |
| 计量结果、结算规则 → 事后金额 | **结算**。最终金额可以依赖使用或交付。 | **文档和样本**，Harvard 明确是会话支付。时间上属于报价之后，研究报价的总作用时不可作为事前调整项。 |

如研究“报价对目标人群累计减载时长的总作用”，以发价前冻结的合资格目标为分母。参加、开放、接单、指令和执行属于中间环节，按参与或成功执行筛样会改变目标。明确拒绝、未接受而确证没有任务执行时，任务贡献可记 0。送达未知、遥测缺失和是否执行不明分别标记。限定为已接单车辆研究技术执行时，另列对象、分母和选择条件。对于同一站点共享配额或邻时段移时，记录共同调度单元和相邻曝光，分析时需考虑车辆之间或时段之间的影响。

原自动生成候选可按记录可用时刻生成预计离站余量、申报需求差和历史功率等候选。候选进入关系表要先核业务含义、时序和测量范围。此轮的箭头是可审阅的业务假设与证据表，尚无整图的现场识别结果。[现有候选生成记录](../b1_auto_resource_factors_20261104/README.md)

## 最小同场数据合同

| 记录与主键 | 同一场需保留的最小字段 |
| --- | --- |
| **任务** `task_id` | 站点、产品或策略版本、报名及任务开始/结束 UTC、目标方向、请求量 kW 及请求时窗、基准功率规则与版本、预期采样率和计量时钟。 |
| **资格及邀请** `task_id + resource_id` | 报价前冻结的合资格车辆或账号范围及排除原因，匿名稳定 `resource_id`、`station_id`、能对接的 `session_id`。未连接允许空会话。保留未邀请、已发未确认送达、已送达、拒绝、接受、未回执与取消，各有时间和来源。若一资源多次报价，用版本键及生效区间保留历史。 |
| **报价与事前状态** `task_id + resource_id + offer_version` | 实际发出的价格、币种、单位（元/kWh、元/次或折扣比例）、折扣所依基价、发送/送达时间、适用区间、分配规则或随机组。对事前 SOC（%）、目标 SOC 或所需电量（kWh）、预计离站 UTC、初始电流/功率、可调功率、站点容量/占用及市场信息，保存量测或生成时刻和系统可用时刻。 |
| **参加及开放、调度回执** `task_id + resource_id + command_id` | 接受/退出时间、承诺的功率 kW/时长 s/可用窗。保留下发、桩端收到、实际生效、变更、解除时刻与执行状态，期望/生效功率 kW 或电流 A、故障及拒绝原因。对未调度但已接受者保留记录。 |
| **遥测及结果** `station_id + session_id + meter_time_utc + sequence` | 经会话—任务映射连到同场和各指令，保留任务前、执行、解除后原始功率 kW、电流 A、累计 kWh 和状态，另存参照功率来源、有效降幅规则、累计秒数、减载 kWh、恢复/回补指标及缺测/截尾。多指令和多任务重叠时需保留关联及优先顺序。 |

第一批对齐只需覆盖有报价和无报价对照、拒绝或未响应、接受未调度、执行、提前退出、可观察恢复与截尾等不同路径。先逐条核对键、时间、单位、去重规则和零值，再预先定义哪些路径能估计什么。选定报价前的所有资格状态用于分母，缺表计者保留记录并说明可观测结果覆盖。
