# v3 为什么仍删掉真实短响应（只核查，不修改）

结论：用户指出的问题成立。v3仍是“左右平稳、中间孤立就改值”，没有建立真实性证据。把一分钟格换成十秒格，只改变了哪种物理时长被当成单点，没有解决单点等于异常的错误假设。这偏离了“不直接压孤立点”的要求。

## 失效在哪一步

- `candidate.py` 在 CPOP 之前把疑似点回填成两侧水平。36个10秒真动作配对输入（12个基础任务）全部被该规则明确选中，全部在指令边沿保护范围外；不是CPOP原本分不出来，也不是时长计数先把它删掉。
- 一个普通噪声例子：第520秒原量测约.9463kW，原CP保留约.9463，新版拟合只剩.0051，低于.15阈值。强制回填是直接原因，后续阈值只是显示了损失。
- 指令只用于保护边沿前后一格。在10秒模拟中是约一个10秒格的保护，在100毫秒记录中是一个100毫秒格的保护；没有建立响应延迟、执行状态、动作方向/回撤的联合解释。保护窗之外不等于异常。
- 10秒真实gap被错误填平是同一规则反面，随后最长连续时长把填平的两段连在一起，放大时长误差。
- 开发检查已经明确展示单格真动作被抹掉，却以“已记录已知失败、最终不采用”继续推进全比较。本应在开发阶段就据此否定该规则，不能用事后不准入代替遵守前期设计约束。原试验记录保留，不改写为通过短响应安全测试。

## 100毫秒数据与指令到底有没有新增信息

**有潜力，但上轮没有完成关键验证。**

1. 上轮有真值主试验用的是独立模拟10秒观测。一个10秒真动作只有一个格，算法没有拿到这个格内部的100毫秒子轨迹。真实100毫秒数据是另一批记录的辅助扰动试验，没有参与这些漏检样本的判断。不能由“10秒格上的10秒动作全漏”推出“100毫秒数据也不能识别10秒动作”。
2. 同一个10秒过程若真的有100毫秒观测，约有100个时间格。可以核查变化是否在多个子样本上持续、起落形态和指令变化是否对应；这种时间细节确实是十秒均值没有保留的信息。但它仍是同一电流通道，不是独立故障真值。
3. 若采集毛刺只持续很短时间，细采样可能显示它只占少数子样本；若异常本身也持续十秒、形状与真实动作一致，仅增加同通道采样不能保证区分。必须验证异常的持续时间与形态，不能预设所有异常都是单个细点。
4. 指令提供任务起点、方向和目标，可能帮助核查对应动作、延迟及恢复；它不是实际响应标签，也不是无调控参考功率。“没有新指令边沿”不能判定真实动作不存在，“指令附近变化”也不能自动证明是响应。
5. 目前整理好的144个100毫秒事件来自18个recording，每段仅指令前5秒到后15秒。可用于局部起变/跟踪核查，不能直接证明30分钟全过程时长。已有原始电流/指令时间间隔中位21ms，上轮仅核来源、未进入候选判断；没有标注真实故障或潜在干净电流。原始完整Parquet路径在既有`real_prepare.py`中，是否可组成更长、完整且同任务对齐的窗口须另核，不能拿其他事件片段补成长任务或编造缺失数据。

## 更合适的方向（未开始实施）

先做“同一事件内部的跨采样尺度证据核验”，暂不继续选新滤波器：

- 从同一条原始细轨迹构建100毫秒、秒级及任务所需时间格，保留对应关系。验证10秒真实动作是否真的由多个细样本支持；不能把另一批100毫秒记录的稳定性成绩当成粗任务真值。
- 把指令用于解释响应全过程，包括允许延迟、持续和回撤，作为支持证据而非硬排除规则。先检查这些证据是否能在未见记录上区分短动作与故障，再决定模型。
- 不预先删除或回填观测。只有独立量测质量信息、可验证的多通道证据或经验证的观测故障模型支持时，才研究分离量测误差；原始计量与真实短gap保留。仅凭“很短/很孤立”不能作修改依据。
- 如果要做下一轮有真值比较，应在同一实际细采样尺度上同时包含持续多格的短响应、单格极短响应、短毛刺和持续异常；统一参考/指令/采样/时长定义给原CP、LABS和候选。先验证信息提供的区分收益，再测时长；不能靠剔除极短动作、填gap或扩大不确定区间算收益。

这是一项信息与定义的核验方向，尚未证明必然有效，也没有在本轮启动新算法或新实验。仍限定第一部分，原CP/LABS对照、旧科学结果、生产代码和报告保持。
