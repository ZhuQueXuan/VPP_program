## 连续任务怎样接

EV是同一次充电会话，真实申报离站时刻固定在第120分钟；源储站级状态运行到180分钟。第一任务0—30分钟，第二任务60—90或90—120分钟。第二任务只在到来时进入规划。

每次输入B2的剩余需求都是 `b×剩余分钟/60＋实际欠账`。第60分钟剩余60分钟、欠账为零时，原B2可能正常提供预测；欠账为正且不满足旧模型关系时，返回不可用，不删欠账迁就模型。第90分钟只剩30分钟，超出B2行为模型范围，该EV的新方案不发送。PV/储能仍可参与，但必须连同已有EV恢复义务一起通过共享恢复检查。

B3读取B2实际五条事件轨迹及概率，计算预计减载和最坏轨迹边界；预测期望只用于预期量记录，准入采用保守物理储备。即使B2预测参加概率很高，也不构成控制许可。方案确实发出后，独立模拟实际接受/拒绝和执行；A=-1未发、0拒绝、正值接受状态分开。

本轮明确授权B3在任务后调度充电回补，可比B2原恒定回补预测更早偿还欠账。B2原回补保留为预测/可行见证，不能声称修订后的实际控制曲线仍等于原预测。B3不预充，不把第一次欠账转给新会话；EV必须按原120分钟期限恢复，储能在180分钟恢复。

准入同时预留“EV最大欠账”和“EV零响应下源储最大供给”两个分量最坏情形，形成保守共享恢复见证。它们不是一个同时发生的真实情景，也不是最优容量求解；拒接表示当前固定策略/假设下不接，不表示所有控制策略都不可行。实际反馈只用当前EV/PV观测和上一格储能执行因子。下界被观测推翻后，状态中的失效标记保持，不因下一格暂时恢复就自动重新承诺。

## 有限验证结果

20个新独立站点种子×两共享余量×两到达时刻×三配对执行机制，共240变体、43200分钟。相同基础站点/变体不当独立样本，无新拟合/选模。场景、协议和代码在主生成前冻结。

| 执行机制 | 运行数 | 两次请求合计 | 接受/拒接 | 已接服务全部分钟达标 | EV按120min恢复 | 站级末端恢复 |
|---|---:|---:|---:|---:|---:|---:|
| 理想执行 | 80 | 160 | 84 / 76 | 84 / 84 | 80 / 80 | 80 / 80 |
| 声明下界内偏差 | 80 | 160 | 84 / 76 | 84 / 84 | 80 / 80 | 80 / 80 |
| 下界外严重降额 | 80 | 160 | 44 / 116 | 0 / 44 | 76 / 80 | 76 / 80 |

全部轨迹的共享约束最大数值残差3.11×10⁻¹⁵kW。严重故障的44项服务失败和4条未恢复运行保留，不能写成故障下仍保证成功。控制流程保留实际欠账、限制动作并阻断后续新准入，不代表损失已经消除。

共实际发送238项EV方案，128项接受；78次正欠账查询被B2范围门阻断，157次第二任务EV查询仍在原模型支持范围内。后者是预测查询数，不能当实际接受或服务成功数。第二任务分别在60/90分钟到达的120条运行中，站级接18/62次；90分钟的接入由可用源储承担，不能称B2已支持30分钟剩余期限。

额外将旧D120前两个种子块的24条场景完整运行防护策略，共864个5分钟步。理想/下界内各8运行，分别接9项服务并全部达标/恢复；严重降额8运行，既有8项已接服务发生在故障前，均完成，但末端只恢复2/8。这个样本没有覆盖所有“故障发生于已接服务期间”的分支，因此另构造一条专项：第10分钟故障、第15分钟观察后退出、后续新任务阻断，失败与欠账不删。旧三策略成绩未改，这里不宣称新策略优于原策略。

## 检查、失败及修复

- 两轮56项开发回归，原B1合法函数逐项相等；二元小数/字符串/缺失、非法模型版本、许可、任务身份、时点及旧B3状态检查通过。
- 独立核验1128976项积分/递推/功率/授权/预测消费/保守见证/旧闭环检查通过；这不是1128976次独立试验。
- 20个种子块、60组未来因子/未来任务/后续退出前缀检查，加原预测返回值隔离和24个并发查询，共147项检查通过。
- 校验发现严格原生数值类型误拒NumPy真实状态标量，会导致旧闭环不必要退出。修为接受有限Real数值，继续拒绝布尔、字符串与非有限值。原文件和初次开发回放保留；原冻结清单不改，以[修复身份记录](corrective_identity.json)核对前后SHA。主240条轨迹与成绩SHA保持，不重跑或覆盖。
- 针对NumPy边界的13项回归通过。两处测试正例最初分别选了无控制接受的欠账状态、受限余量本应拒接的任务；均是预期写错，已留[说明](numeric_boundary_test_failure.json)及[修正记录](public_scope_checks.json)，没有据此改生产算法或成绩。
- 项目原369项保护文件、74资源模型v15、既有B1/B2/B3及会议报告保持。新科学入口修复均留原件。没有新依赖、GPU、训练、界面、上传或提交。

主240条运行约13.50秒，旧防护24条回放约3.77秒，本机CPU。复用现有NumPy与SciPy求解器；设计前核对[维护中的SciPy开源库及BSD许可](https://github.com/scipy/scipy)和[Pydantic严格模式](https://github.com/pydantic/pydantic/blob/main/docs/concepts/strict_mode.md)。本次主要是保留已有数值核的边界适配，使用显式原值检查，没有引入另一套模型/schema依赖。数值类型兼容问题已经单独回归，不能以“严格”代替正确的输入语义。

## 怎样调用与复核

在项目根目录的新Python进程中调用，不需选择研究重复号：

```python
import json
from pathlib import Path
from b123_api import predict_single, initial_state, assess_arrival

case = json.loads(Path('data/B1_B3_continuity_v1_20261028/cases.json').read_text(encoding='utf-8'))[18]
public = case['public']
forecast = predict_single(public['evs'][0]['declaration'])
state = initial_state(public)['state']  # 仅新会话起点初始化
decision = assess_arrival(public, state, [], case['arrival_stream'][0])
```

连续调用必须传入真实递推状态，不能再次初始化。`initial_state`只建立本协议的新声明会话，不能认证真实设备状态。剩余需求可用`predict_remaining`单独查询；实际状态递推及完整回放实现、输入和记录分别见[controller.py](controller.py)、[runs.json](runs.json)，不把演示初始状态当现场反馈。

其他函数：`extract_event/fit_factor/predict_factor/learn_graph`为B1；`assess_single_joint`兼容D122单次共同域；`query_previous`处理D120原三小时物理模型的5分钟查询。两种B3合同分别命名，不能混用EV期限、时标或状态结构。缺输入/域外/不可行/拒接/下界失效各自返回明确状态，承诺始终null。B1提取成功也可能包含缺测导致的不可算字段，必须同时看`features.stage/request_coverage`，不能只看外层status。


目标必须尚不存在且位于项目work内。命令只读源码/模型/轨迹/收据并写新目录；拒绝覆盖既有目录，不调用旧核验脚本，不重算原实验。已运行的实际审计见[新审计目录](../b1_b3_stability_audit_20261028/verification.json)。

## 完成判断

前三算法在这组明确支持条件下的稳定入口、两次调用连续状态和失效处理已完成有限验证，可以结束本轮。现有D123历史/表示分支仍不默认采用，不为研究方向名称再训练到胜出；B1在闭环中的观测解释与B2预测、B3控制各有用途。

本轮不宣告前三算法面对所有设备、任意任务或现场故障都已完成。跨机制研究、正式时序方法定位、真实接受/控制与可靠性证据、正式90%验收定义，仍属于后续完整研究的条件。本轮给出适用范围和稳定性计算口径，不把这些研究缺口静默记为通过，也不把它们扩大为当前必须再做的新实验。
