# 正式B1根合同与参考移植独立审查

审查范围：只读`b1_algorithm/contracts.py`、`api.py`和`reference/core.py`。未修改他人代码，未启动大研究或报告。

## 已核对成立的部分

- 参考预测绑定task/user/meter身份及完全相同的计量格，available_at不晚于通知。事件在身份核对后将绝对计量时间、请求和通知时间统一转换为任务起点相对时间，未将分钟与秒或不同时间原点混用。
- EventResult的结果为共同原始参考减实际功率积分，不使用过程拟合电量。群体入口检查所有事件，没有隐式丢弃失败事件或只保留响应者。
- 群体入口逐事件核对结果窗口、q、事前任务声明与原task相同，结果值也须等于同一process的eta_raw；不同窗口/请求不能静默合并为一个目标。算法/事件schema版本分别核对。
- 因果入口把事前任务、事前X、无干扰、一致性、相同结果定义及分配假设分开；未知假设只输出标准化关联。支持通过不是因果已证明，known_pi本身不证明随机。
- 根事件ID最终只接受非空字符串，不将数字1与字符串"1"隐式合并；独立effects入口仍保留有类型的ID区分。

## 本审查提出并已修正的合同问题

1. 数值数组先统一float化会使混合布尔被掩盖。根与reference均已改为转换前逐元素检查，拒绝布尔、字符串和非Real。
2. 数字/字符串身份隐式归一可能错绑参考。根已采用字符串唯一合同，并要求上游显式转换。
3. 事件结果只互相比窗口/q而不与自己的task核对，会掩盖错配。根已增加窗口/q/声明/processη逐项核对。
4. 非有限reference元数据在错误结果中残留，会破坏JSON输出。根已先校验元数据JSON并在失败时清空不安全的reference/process。
5. 巨大Python整数转float可能直接OverflowError。根number与effects scalar均已安全拒绝超出float64域，不能冒充有效数值。

[root_contract_probe.json](root_contract_probe.json)记录只读小例：混合布尔、身份歧义和超出float64域均按合同拒绝，并保存审查时根文件SHA。根还在开展完整链验收，本小例不替代实际过程或参考运行。

## 参考模块的信息边界

正式ReferenceWindow只接通知前功率、已完成非事件历史均值、日历与事前可得温度，并检查输入可得时间不晚于通知。未见旧RIDE的实际离站、未来会话电量中位数等路径。历史源ID与时间戳是调用者提供的事实声明，程序能检查一致性，不能证明资料确实来自该历史日期；README已明确这一边界。

参考训练、校准和未见用户预测角色分开；模型拟合/校准截止时间不能晚于查询通知。窗口校准的半宽不是逐点噪声或同时轨迹带，不能直接用于过程参数或完整因果误差传播。

## 科学声明保持

新B1的默认平均作用对输入事件等权，按用户分折与聚类不自动改成每用户等权。用户聚类同时带需要用户簇独立；站级共同冲击可能要求不同分组或推断设计，无干扰不自动保证独立。参考与过程误差未传入全链区间，本版只声明条件于供给结果的推断。标准多档AIPW及合法二元G1属于成熟方法适配，不因代码整合自动成为新的因果创新。
