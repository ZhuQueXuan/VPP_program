## 2. 这份代码究竟回答什么

中心问题是：**在气温、设备状态、日历和已有历史等可观察条件相近时，改变资源实际收到的激励，期望功率会改变多少；这种作用如何随类型和状态变化。** 它服务于课题一的因素分析与条件敏感性研究，可为后续特征库提供候选特征。

例如，空调负荷下降可能同时涉及电价、气温、占用与设定温度。代码试图从这些共同变化中估计激励对应的增量作用。能否解释成因果，仍取决于激励分配、未观测共同原因、公布时点和处理/状态的先后关系；机器学习拟合本身不补足这些条件。

同事交付包含“构造带真值的实验数据、估计方法、简单对照、结果评价”整套离线研究流程。它没有替我们建立完整单体物理模型、真实最大可调容量、运营优化、自监督分类或可直接部署的在线系统。

## 3. 各文件具体干什么

核心原件位于 `work/vpp_dml_review_20261017/vpp_dml_framework/`，根目录ZIP原样保留。

| 文件 | 实际功能 | 对研究的作用 |
| --- | --- | --- |
| vpp_dml/simulate.py | 构造天气、四类资源、市场价/实际激励、状态、功率和true_*真值 | 在已知答案的合成场景中检验是否恢复设定规律；实际未读入实测底座 |
| vpp_dml/features.py | 制作历史功率、参考价偏差、当期/滞后/前导激励、状态等 | 把原始长表转为模型变量；原实现依赖连续小时行及固定字段 |
| vpp_dml/splitting.py | 时间块交叉拟合与资源分折 | 减少训练与评价混用；原交错周折是回顾策略，不等于完整向未来盲测 |
| vpp_dml/nuisance.py | 结果与激励两组辅助预测，计算交叉拟合残差 | 剥离协变量可预测的共同变化，默认LightGBM；缺失该依赖时退化为sklearn直方图梯度提升 |
| vpp_dml/final_stage.py | 线性基函数、因果森林、神经网络R-learner三种选择 | 用剩余变化估计激励敏感性及状态异质性；三者是替代方案 |
| vpp_dml/pipeline.py | DMLSpec配置、组织拟合、输出系数、参考基线与离散度 | 将步骤连起来；原新样本基线接口和识别阻断仍有缺口 |
| vpp_dml/diagnostics.py | 激励变化/共线筛查、最终阶段留出、安慰剂、时间块自助法 | 提供核查工具，不保证所有识别条件成立；原诊断默认不在fit前阻断 |
| vpp_dml/baselines.py | 朴素回归和带控制/交互线性回归 | 判断复杂方法有没有额外价值；新任务比较需同特征公平设置 |
| vpp_dml/evaluate.py | 读取合成真值，算效应/基线误差、资源画像聚类一致性等 | 只适用于对应真值体系，真实数据不能直接沿用这些准确率 |
| experiments/run_benchmark.py | 传统对照、S0—S5消融、三最终阶段、反例、安慰剂、识别失败和调频实验 | 展示固定模拟中的方法比较；S0不是本项目当前程序的实际成绩 |
| experiments/run_coverage.py | 重复造数/拟合，比较聚类与独立样本标准误的覆盖率 | 检查区间校准；去偏覆盖率与直接覆盖真值要分开报告 |

## 4. 处理步骤与五个激励特征

原主能量模型以实际有功功率P为结果。它把能量激励与过去7天同小时平均激励比较，形成高、低两段，并加入上一小时高价、下一小时高价、当期绿色激励。

| 特征 | 希望研究什么 | 必须具备什么证据 |
| --- | --- | --- |
| phi_Ep：高于参考价 | 高价一侧的条件功率变化 | 实际作用于该资源的价格/补偿、可靠历史参考、同类状态中的价格变化 |
| phi_Em：低于参考价 | 低价一侧是否存在不同斜率 | 同上；不对称不自动证明心理损失规避 |
| phi_lag：上一时段高价 | 当期功率与此前激励的关系 | 连续同对象历史、恢复窗口和其他控制变化；系数本身不是恢复时间/能量 |
| phi_lead：下一时段高价 | 提前公布的激励是否引起预冷/预充 | 必须证明激励在当前决策前已公布，不能用事后实际价格充当提前信息 |
| phi_C：绿色激励 | 绿色积分/补偿变化的功率作用 | 真正发送的可比较激励及适用窗口；不等于设备绿电属性或碳减排量 |

代码模拟器直接假设未来激励已知，真实接入必须新增公布时间与版本核验。参考价窗口7天和90天实验规模属于本版本设计，不能当成所有资源的通用研究标准。物理状态也须以激励公布前为准；小时开始前的SOC/室温可能已经受提前公布的激励影响。

第一阶段“分别预测两件事”：

1. 给定天气、状态、历史等，通常会出现怎样的功率；
2. 给定同样条件，通常会分配怎样的激励。

扣除这两组预测，得到“未由这些条件解释的功率变化”和“未由这些条件解释的激励变化”。第二阶段再学习二者的关系，并允许作用随状态而变。这是本代码中双重机器学习的主要计算结构。遗漏重要共同原因时，扣除过程仍可能不充分。

第一阶段默认LightGBM；第二阶段才从线性基函数、因果森林、神经网络中选择。线性基函数便于解释与总体效应报告，森林用于较复杂的状态差异，神经网络是另一种函数形式；复杂不自动更好。D069固定对照已表明当前项目任务数据上没有稳定优势，不能把模型名称当性能保证。

## 5. 输出分别能怎么用

| 输出 | 可以怎样理解和使用 | 当前解释边界 |
| --- | --- | --- |
| effects_frame / theta | 每条记录在给定状态下的激励敏感性估计 | 条件平均作用，不是每个用户的确定反应或所有工况通用斜率 |
| ate / ate_ci | 平均作用及统计估计不确定性 | 原解析区间仅线性最终阶段；有限独立组与设定偏差仍有影响 |
| baseline | 参考激励水平、既有状态与历史下的期望功率 | 不等于物理最大功率、整段从未激励的独立轨迹或合规结算CBL；原接口主要针对已拟合行 |
| dispersion | 条件残差的波动程度候选指标 | 原为同批样本拟合/预测，未独立校准；不能当任务兑现概率或保守容量 |
| feature_library.csv | 将记录级敏感性汇总为每个模拟资源画像，附标准化效应 | 可作为分类候选输入；不表示已完成多能力自监督分级分类 |
| sensitivity_by_type.csv | 查看四类资源估计均值与模拟真值的差异 | 同模拟样本的描述，不能直接代表真实行业平均 |

在给定部分线性模型、参考激励特征为0的设定下，参考基线恢复式为 B=ℓ−Θᵀm。ℓ本身已经含有对预期激励的平均响应，因此不能直接把ℓ叫无激励基线。这里的参考状态仍条件于已有历史/状态。

AGC子模型另用R“申报调频容量”为结果、DA“容量激励”为处理，估计申报量随激励的变化。它没有核验设备真实可用容量、跟踪精度或秒级端到端响应。模型支持不同结果变量，但要另配相应业务定义、数据和评价。

## 6. 现有资源调研需要保留什么、增加什么

六类曲线、公式、参数、约束与baseline仍是基础。建议每类后续调研分清以下四层，按证据决定能做到哪一层，不必每类同时做完：

| 层次 | 研究问题 | 需要的核心证据 |
| --- | --- | --- |
| 物理能力 | 在当前状态及约束下能调多大、多久，怎样恢复 | 设备机理、功率/能量/舒适/工艺边界、状态与独立参照 |
| 指令执行 | 收到某项设定后实际怎样变化 | 发送/接收/生效时点、模式、设定、实际功率及失败记录 |
| 经济激励 | 改变实际价格/补偿会不会改变行为 | 实际收到的激励、合同传导、分配机制、可比较变化和主要共同原因 |
| 选择与授权 | 会不会接受、开放多少、何时退出 | 邀请、接受/拒绝、授权、手动覆盖、使用/生产需求；自动EMS需研究策略而非机械套个人心理 |

没有收到任务、设备没能力、控制未生效、没有授权与不愿参加，都可能表现为没有功率变化。物理与控制研究帮助辨别这些情况，统计估计器无法凭一条功率曲线自动区分。

## 7. 调研资料以后怎样组织才更能支持这些方法

建议每项研究先确定一条可评价的问题，再整理下列材料：

1. **对象和作用层级**：单设备、车群、楼宇、场站还是运营主体；研究参加、开放、执行还是恢复。对价格的哪种作用，是否包含提前响应及跨时段总作用。
2. **物理依据**：曲线、公式、参数、约束、适用工况与参数来源，继续现有做法，注明模型近似和设备差异。
3. **信号与决策链**：市场价如何通过合同成为实际激励，谁看到、谁决定；公布、送达、允许决策、生效、测量及上传时点分别记录。自动与人工策略不要混在一项未知偏好里。
4. **可比样本和变化来源**：多个补贴档、随机邀请、对照或可解释的外生变化；只在相同小时固定切换的电价可能无法与时段作用区分。更多重复行不等于更多独立干预。
5. **事前输入与事后结果表**：同一实体/会话/任务主键，统一单位、功率方向和采样窗口，保留缺测、拒绝、零响应与失败；不把事后接受与执行结果加入事前效应控制。
6. **公平检验**：先隔离完整主体/事件或外层未来时段，再在训练侧完成处理与拟合；同变量简单参照、零作用对象、类型与状态分组、域外和最差案例一并报告。

没有可调容量参照时，不用未知“可调容量”作归一化分母；可以保留物理单位或采用有据的额定值尺度并注明含义。没有绿色补偿、问卷或提前价格记录时，裁剪相应研究对象与代码特征。DMLSpec和适配层可以按数据重新定义处理、结果和协变量；原build_dataset仍有硬编码字段，不能只删CSV列就当适配完成。

## 8. 同时代码本身仍需完善

研究不应单方面迎合程序。原小时流程尚需真正识别阻断、严格时钟/主键校验、公布时间与状态先后、完整外层留出、新样本基线推理和独立离散度校准。同特征透明参照与负控也应保留。

D069仅在任务级适配中补了隔离/阻断和新的评价，未修好原包所有小时应用能力。已有模拟接入结果中总体均值近似而负控失败，说明后续必须检验类型差异与零作用，不能把均值接近或“因果森林”名称当作识别成功。

建议保留原六类有限成果，后续每个选定对象增加一张“物理/技术/激励/选择证据及可支持输出”清单，选择一个证据可闭合的问题推进。原代码作为可选研究工具，与任务一的时序特征、任务二的物理与行为证据、任务三的后续分类分别衔接，当前不升级研究阶段或自动启动新实验。

方法原理可参照[DML原论文](https://doi.org/10.1111/ectj.12097)与[EconML因果森林官方说明](https://www.pywhy.org/EconML/_autosummary/econml.grf.CausalForest.html)。后者页面为0.16.0文档，本机上轮运行0.17.0；具体实现及使用边界仍以本次已读原代码和D068/D069收据为准。
