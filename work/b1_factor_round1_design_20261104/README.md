# 第 2 点 · 驱动因素与作用关系首轮设计

2026-11-04。设计草案，供总管审查。建议先做 **R1：车辆事前充电状态怎样影响降限后的实际跟随**。ACN 已支持一段窄范围关联。英国 Electric Nation 的 CrowdCharge 公开字典进一步区分后台计算限额、桩端记录限额和实测电流，适合核对一个此前无法区分的问题：限额已经在桩端变化时，超出车辆当前用电需求的那一段降限，是否仍会表现为同等的电流下降。先准入，后比较。主 ZIP、覆盖率、同场连接和有效确认块仍待核验。[公开数据入口](https://commercial.nationalgrid.co.uk/electric-nation-data) · [官方字典](https://commercial.nationalgrid.co.uk/downloads-view/81670)

首选采用一项预先定义的状态与限额交互。将旧 ACN 的跨事前电流边界判据转成同一实测电流结果的加性基线，并让候选只多用一个物理上有含义的交互项。两法共用记录、原始输入、标签、模型形式、分组、正则预算及计分方式。分析会分别回答同等降限幅度和相近前态下两侧的实际差、交互能否改进幅度解释、以及哪些后台降限同一采样点尚未见桩端跟随。最后一类是 ACN 旧 354 窗缺少后台列而无法区分的情况。现有时序约束 PC/KCI 保留用于结构候选筛查。它输出候选连接，无法与按安培输出的模型直接比分。旧流程可能在无条件筛查先删掉纯交互。更换条件独立检验无法恢复已删边。[原 ACN 比较](../b1_acn_execution_relation_20261104/README.md) · [因素比较](../b1_response_factors_20261104/README.md) · [首轮协议](protocol_draft.json)

现有 ACN 开发记录足以在下一轮尝试同条件的短窗幅度比较，结果单列为开发证据。CrowdCharge 的确认分钟端点另行准入。此轮只做有限元数据核查。若单独的小表或字典已经能回答文件结构，先用该材料。整库下载与确认评分留待下一轮审查。

R2 恢复关系单列，先区分指令解除后的回升、恢复目标及未恢复或掉线。R3 保留报价对参与和实际用电的两个结果。iFlex 有组日分配和实测电量，但公开设计缺少改派和概率日志，同类四档组日已进入旧研究。Calgary 有随机固定奖励设计，原始表仍未取得。两者都缺逐任务参加机制的完整分母和回执。详见[三条关系](relation_questions.md)和[数据准入摘要](data_availability.md)。

## 请总管审查的三个决定

1. 同意把首轮执行问题限定为 **家用 CrowdCharge 已在充电的非暂停降限、分钟尺度电流变化**。接受桩端实际限额的条件关联作为本轮证据级别，后台计算与桩端记录之间的差异单独列账。
2. 同意按协议先锁定未见设备组和后期整周，确认数据只返回允许的元数据。认可 0.5 A 且至少 5% 的误差改善、逐周稳定性、覆盖及关系方向的采用门。达不到数据准入门时保留当前证据并停在准入，不借用旧测试。
3. 同意 R2、R3 继续独立列为待证。R3 优先核实分配、同场资格分母和计量，允许在随机设计确证后先给报价分配对结果的总作用。参与机制与 EV 连续补偿问题保留各自缺口。
