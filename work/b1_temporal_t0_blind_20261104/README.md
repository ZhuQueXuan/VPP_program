2026-11-04。已用现有真实开发数据逐张看完24段充电和12段热泵曲线，并回查关键原点。样本按元信息冻结，逐条判断时只看匿名曲线、原点及必要控制记录。首审为单助手暂定参照，目前缺独立复核及一致率。当前节点是总管审查，表示比较和训练均待后续放行。

**提请总管优先审查功率变化先后、运行保持与中断形态。** 充电可区分持续衰减、中途低谷和长时间保持。运行维度现阶段可描述持续运行、持续低位、退出和短跌，严格的单次或反复中断正例太少，暂不足以建立该类别的比较参照。热泵三段中位数会压掉短脉冲，例如 HP07 实际有约5 kW峰，三段中位均低于82 W。任何分段规则调整留待总管审查。

回升留作次目标。热泵停止后功率上升可描述早晚及反复，但常在约数小时后出现。充电仅3个用户有完整可判回升，先独立复核并补足两类结果和可用控制阶段，才适合做共同评价。所见功率上升、低位和回限仅是原记录的观测关系。EV22 约125 A、48–49 kW，留在原分母，后续若研究普通交流充电需核设备类别。

## 热泵台账与重算

- 原 Stata 文件659,782行，按原户和事件ID核对了287组起止、9户。保留253次正时长、34次零时长。全档7个同户同时间额外行均在本轮定义窗口之外。时长以带时区起止转 UTC 之差为曲线横轴，5个跨夏令时事件另存源时长和3600秒差值。
- 全287事件中，21个全窗有超过450秒的间隔，17个全窗至少一个功率缺值，1个后窗有另一干预，1个后窗为空。户记录总体首尾都跨过目标窗，台账另列窗内两侧边界不足、长缺口、逐通道缺值、重复行与后续控制。上述问题可以重叠。
- 在253个正时长事件中，218个具备全窗功率覆盖，226个通过前段与干预内各自的覆盖检查，233个后窗有功率覆盖且无新干预。每组均涉及9户。这些是记录覆盖数，末段参考与形态可判性仍由审阅确认。
- 抽样覆盖9户、12事件，11正1零，同户至多2段。充电复用24个原冻结包，按哈希重编盲号，9,913点逐文件字节相同。热泵3,298点逐源行核对了原时间、UTC、相对时刻和六列通道，按原存储精度复原一致。台账287×4阶段及75个盲包文件的冻结哈希均已复核。
- 在本目录运行 audit_pack.py 可复算台账及首审计数。build_pack.py 通过 --output 指定新的工作目录可重建材料。初次建包因源时长与 UTC 时长差异触发断言，改为保留两者后再次执行，中间另处理了布尔类型序列化。首次源点审计直接拿 CSV 双精度和 Stata 单精度比较，改为按原字段精度还原再核。判读用包冻结在先，源点审计时保留了原包和首判。

当前证据来自开发记录。旧确认与外站观测未读取，拟合模型数为0。
