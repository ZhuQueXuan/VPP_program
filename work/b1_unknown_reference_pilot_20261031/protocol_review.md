# 小规模复现协议独立审查

2026-10-31。审查对象为根执行者提交的小规模试验设计；此时实现和输出尚未提供。本文仅评估协议，没有拟合、生成数据或改动其他文件。

**结论：可按本协议开展有限复现。没有发现需要增加模型家族或扩大样本才能处理的阻断项。** 以下口径须在执行前写入冻结协议；它们限制可宣称的结论，不要求扩大比较范围。

## 1. 规模与隔离核对

| 阶段 | 约定用途 | 独立用户/任务数量 | 审查结论 |
|---|---|---|---|
| reference train | 训练4个固定配置 | 64用户×2非事件=128任务；共同8horizon，共1024训练行 | 正确；预测器使用同一行集合、同一合法特征和train内标准化 |
| reference validation | 仅内部选参考 | 32新用户×2=64非事件 | 可用实际非事件观测功率作标签，不用模拟真参考选参；评分和并列规则先固定 |
| process development | 估总误差Σ/σ，选TF λ | 32新用户×2=64非事件 | 同dev估Σ与选λ属于开发选择，允许；不能称为独立误警验证 |
| evidence calibration | 冻结后校准任务证据 | 48新用户×2=96非事件 | 与训练/开发/选参考隔离；按用户最大值处理两任务依赖 |
| pipeline validation | 冻结后只评价 | 16新用户×2任务×strong/weak/null=96变体，32基础任务 | 不据这一步改λ、σ、Σ、参考配置或score；失败如实保留 |
| final pilot test | 小样本新用户评价 | 4新seed×32用户×2任务×3变体=768事实，256基础任务 | 768是配对变体数，不能写成768独立试验；仅4块，稳定性结论有限 |

“所有用户不同”应指阶段间及测试块间隔离；同基础任务的strong/weak/null必须保持配对，不能为凑独立数改用户身份。每个用户两任务也不独立计数。整周平移须保持日历，且训练所用历史/标签完成时点早于后续阶段；不仅核任务start，还核完整后窗与历史可得性。

## 2. 模型与比较边界

提升树leaf7/15、GP固定lengthscale0.7/1.5是内部四配置，不作为额外正式算法板块。GP的其他参数（核类型、幅度、噪声/jitter、是否优化）和特征缩放先冻结，不能声称固定lengthscale却在优化器中又学习。horizons固定为 `[0,8,16,25,34,43,51,59]`；两种模型同1024行训练，评价可覆盖共同完整60格。

选定参考给TFstd、TFfull、原CPOP共用。TF的H=I表示直接恢复原生1分钟区间均值向量，本轮没有新的格内潜在轨迹；据此输出计量尺度特征，不宣称识别格内物理时点或适用于15分钟。TFfull的协方差加权属于成熟GLS/广义lasso适配，不能称原创估计器。TFstd是消融，TFfull及CPOP构成本轮过程比较；不增加第三个正式板块。

Σ用dev非事件的整段预测残差估计，LedoitWolf收缩可以处理64条60维残差的有限规模。两个同用户任务存在相关，不能据64行称64独立用户；不影响它作为开发估计，但进一步限制其统计精度。LedoitWolf中心化不等于已修参考均值偏差，偏差须另报。

共同σ来自dev非事件预测残差RMS，包含参考误差和计量噪声。给CPOP的这是“共同总误差尺度”，不能标成已知纯电表σ；不再重复加同一计量方差。CPOP原核心和β=`2*log(60)`保持，内部参数无测试调节。TFstd/TFfull的目标归一化、D2定义、λ候选实际数列和并列规则须写清，防止尺度不同却误记为相同λ含义。

## 3. λ选择和误警解释

λ在dev未发任务上选择：选择满足“32用户中，两任务任一原始正时长”的用户假阳性率≤.05的最小λ。32用户时，这实际等价于最多1个误警用户（3.125%）；2人已是6.25%。该离散阈值较严格，应在结果中直接报告计数。

若全部λ失败，按最低误警人数、再最小λ选择并明确记录约束失败。不得为了通过而追加更大λ、换dev、改物理阈值或使用模拟true reduction。无论约束是否满足，独立cal和test均继续保留完整分母。

此处有一项公平性限制：TF的λ被开发集raw-duration误警目标调过，CPOP β固定。故raw时长误警/漏检只支持“本组配置下的pilot结果”，不能直接当作相同原始误警工作点上的算法优劣。最终相同α的独立任务证据可用于观察功效；同时保留原始时长误差及raw误警，不能只展示更有利的一套。

不要求为了这轮小复现再开展CPOP大规模β搜索。只需明确其固定文献配置与TF开发选择的差异，避免将小pilot升级为最终方法胜负。

## 4. 独立任务证据

校准来源必须是明确未发任务记录（未宣布激励、未下发任务），不能从实际任务的未参加者/未响应者筛校准。所有方法共享同一score形式、扫描长度、α及用户聚合方式；score数值当然可因各自拟合曲线不同而异。原始特征和任务证据是不同输出，校准不把不确定任务时长改为0，也不删因素分析样本。

建议明确：校准每用户两个任务score取max；测试报告两任务max的用户级证据及逐任务结果，分别保留口径。48个校准用户的rank最小p为1/49；α=.05时可达的上尾离散水平为2/49。并列使用保守上尾计数，加1修正。若score还对多个尺度/片段搜索，搜索必须已进入同一个校准score，不能在校准后额外挑最显著片段。

rank是给定冻结score与可比用户分布下的校准，不自动保证时间漂移、其他任务或真实现场5%。test null的用户级误警计数应独立呈现，不用dev达标或α字段代替实际检验。

## 5. 执行与审计要求

所有真值放评价器；训练参考用真实非事件功率、开发估Σ/选λ用非事件预测残差，不读取true_reference/true_reduction。validation/test真值仅评分，不能回流参考/过程/证据。原源码、全局默认、旧冻结结果不改，本轮只写新work过程与明确的新数据位置。

TF数值输出须检查有限值、求解终止/最优性残差及共同时间格。若某次失败，保留失败行并列不可用，不静默用CPOP回填、不只评求解成功样本。H=I时原始积分η给同参考三法应相同；时长阈值、驻留和窗口相同，不能将惩罚压成零当作可靠无响应证明。

本轮可以回答代码复现是否正确、是否有值得继续研究的有限趋势，以及主要失败位置。它不承担正式选型、方法原创性证明、其他任务/分辨率、真实EV、连续因素新估计器或B1整体完成。实现与输出形成后，再进行独立只读核验。
