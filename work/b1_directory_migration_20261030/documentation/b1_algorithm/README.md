## 采用哪些部分

| 部分 | 正式取舍 | 依据 |
| --- | --- | --- |
| 未调节参考 | RIDE条件预测思路＋我们修正后的SafeGBDT；历史均值保留 | 固定GBDT在已有有限比较中明显优于历史均值，选择器无额外收益。删除实际离站、未来会话与事后电量输入 |
| 过程曲线 | CPOP灵活模型＋受观测验证约束的任务模板 | CPOP处理细计量、多平台较好；模板在部分场景有益，不能按真实机制挑方法 |
| 特征与电量 | 原F0阈值、驻留和恢复状态；原始区间积分 | 累计与最长连续时长分开，过程拟合不替换电量；缺测不静默插值 |
| 激励效应 | 多档标准AIPW、用户分折和聚类推断；保留合法简单对照 | 标准得分已与DoubleML核对；不承诺AIPW总比正确回归误差小 |
| 输入输出 | 新任务绑定、时标与可用状态 | 参考不能跨用户、计量点、任务或网格串用；支持诊断与因果假设分开 |

原RIDE的连续剂量、自动单调收紧和原真实数据适配器不直接纳入。本版没有把它们的已知问题带入默认流程。原二元饱和G1保留为合法二元域的独立入口；旧图筛选和历史表示证据仍保留，未冒称已由本轮解决。

## 默认流程

1. 提供绑定到事件的事前参考，或用严格历史记录训练的参考模型预测；输入缺失、时标不明或信息晚于通知则不可用。
2. 10秒、1分钟完整计量记录以原生CPOP为灵活模型，用每1分钟块交错留出的5折预测误差检查阶段模板。模板的验证误差至少相对降低10%，且块均值优势超过1个块标准误，才允许使用；否则保留CPOP。这个选择准则没有置信概率保证。
3. 15分钟只有4个观测格，直接保留原计量格，物理细时点保持未知。R运行故障明确降级到原始F0，返回原因，不能静默冒充CPOP或模板成功。
4. 每事件净交付比例均从同一原始参考差值积分得到；模型选择影响过程曲线与特征，不制造电量增益。
5. 同定义事件结果进入多档效应估计。支持不足不报曲线；假设未确认只返回标准化关联；满足调用者声明的研究假设后才返回条件因果作用与用户聚类带。

门控默认通过6个新开发种子的预登记准入后冻结，随后只在另一批20个新种子上评价一次，未用留出结果调整阈值。开发和留出材料在`work/b1_formal_v1_20261029/process`；那里是验证证据，算法不从中导入Python实现。

这批新留出包含960个配对观测变体，独立单位为20个种子块。任务窗曲线RMSE均值（kW）如下：

| 方法 | 10秒 | 1分钟 | 15分钟 |
| --- | ---: | ---: | ---: |
| 统一正式默认 | 0.021368 | 0.048632 | 0.088553 |
| 原生CPOP | 0.021730 | 0.054346 | 0.102623 |
| 原RIDE模板 | 0.049705 | 0.048168 | 0.077242 |

统一版相对“CPOP＋粗计量原格”的保守版，总平均误差差为−0.002026kW，20个种子块均改善，MC95为[−0.002424,−0.001627]。相对原RIDE，10秒更好、1分钟没有稳定差异、15分钟较差；保留粗计量的精度取舍，没有据此声称物理细节可恢复。统一流程选择CPOP458例、模板182例、原格320例。

正式模板求解器是成功状态可检查、预算固定的适配，其单独精度未优于原RIDE；因此不作为无条件默认，只在观测验证获准时使用。改动见[过程来源记录](process/SOURCE_ORIGIN.json)，原RIDE仍作独立对照。本版的已验证收益属于组合规则，不能归于任一组件全面更强，也不是实测设备可靠性保证。

## 在代码中调用

Python统一入口：

```python
from b1_api import (
    provided_reference, analyze_event, analyze_events, estimate_event_effects,
    ReferenceWindow, ReferenceTrainingRecord,
    fit_reference, predict_reference,
    save_reference_model, load_reference_model,
)
```

`analyze_event`接收任务、区间起止、实测功率、绑定参考和已声明噪声。`analyze_events`逐条核验并批量调用原生CPOP，保持顺序和失败项；`estimate_event_effects`直接消费同定义的事件结果，禁止默默丢弃失败事件。

当前两条计算支路共享参考差值：过程模型给曲线、阈值和时长；原始差值积分给净交付比例η，默认激励效应估计使用这个η。CPOP或模板的选择不会改变原始积分，也不能据此说“过程拟合更好就必然让η的效应更准”。其他过程特征进入因果模块的联合验证仍未完成。

## 开发后的核验

现有检查脚本保留在研究证据目录：

- `work/b1_formal_v1_20261029/verify_pipeline.py`：统一输入输出与事件到效应计算。
- `work/b1_formal_v1_20261029/reference/check_formal_reference.py`：参考输入时序与模型存取。
- `work/b1_formal_v1_20261029/effects/verify_formal_effects.py`：效应得分、分折、状态和边界。
- `work/b1_formal_v1_20261029/process/check_api.py`：过程接口、原生R和故障处理。

本机运行环境是`work/ride_b1_v02_reproduction_20261029/.venv/Scripts/python.exe`。开发时按修改范围运行相应检查；这些检查不是主性能实验，不自动重跑或覆盖旧研究结果。

任务身份须为非空字符串，不将数字1与字符串“1”隐式合并。时间用调用方同一原点下的分钟，过程层内部转为相对请求起点。当前已验证的过程域是请求30分钟、1.5kW、通知提前15分钟、观测从请求前15至后45分钟，计量10秒/1分钟/15分钟且完整规则。域外返回不可用。带噪实测功率可出现负值，原积分不裁剪。

参考预测支持严格1分钟历史、30/60分钟任务、明确的通知前15/60分钟功率与至少两条合法非事件历史来源。其输入范围与过程域并不完全相同；统一调用链必须同时满足两个模块。字段、保存模型和校准说明见[参考模块](reference/README.md)。

效应模块接收外部同定义结果，按事件等权；同用户事件统一分折。详见[效应模块](effects/README.md)。旧二元G1通过`b1_algorithm.effects.fit_binary_saturated`调用，不自动将连续条件粗分组。

## 环境与运行依赖

本机直接复用已经安装的独立研究环境，无需重新下载。Python依赖见[requirements.txt](requirements.txt)。Rscript与cpop是明确的外部运行依赖，版本为R4.6.1、cpop1.0.10；默认路径与关键文件SHA在[runtime.json](runtime.json)。统一入口会检查本机默认依赖身份。

迁移机器时需安装对应依赖并更新路径或显式传`process_config`，不能将缺少R的降级结果算成原生CPOP成功。正式Python源码不依赖work里的原型实现；当前本机R安装位于原研究runtime目录。临时运行证据保留在work，不递归删除文件。

## 输出范围

参考结果始终是预测或调用方提供的参考，`counterfactual_identified=False`。过程特征描述计量格上的阈值和驻留，不推断参加意愿；物理细时点和过程置信区间没有被自动验证。

效应的`support_pass`与`causal_assumptions_confirmed`分开。因果假设声明需要研究设计和数据支持，程序不能证明无遗漏混杂。聚类区间要求原用户簇独立并满足相应统计条件，不能覆盖站级共同冲击；参考和过程的整体不确定性尚未传播。

本版保留原B1/B2/B3稳定入口`b123_api.py`作为历史兼容，新增B1统一入口为`b1_api.py`。本轮没有改变B2/B3、真实数据冻结或原报告，也不表示整个B1或项目验收已经完成。
