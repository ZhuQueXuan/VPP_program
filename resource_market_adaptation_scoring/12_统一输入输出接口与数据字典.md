# 统一输入输出接口与数据字典

## 1. 文档定位

- 版本：V1.0。
- 日期：2026-09-15。
- 上游架构：`11_动态资源市场适配系统总体架构.md`。
- 目的：固定资源提交、市场任务和评分结果三类接口，为资源能力适配器、统一评分程序、自动测试和后续平台对接提供共同语言。

本版先稳定业务含义和数据结构。光伏、储能、充电桩是第一批实现对象；其余 13 类资源沿用同一外层接口，专属参数在后续逐类接入时补充验证规则。

## 2. 三个接口怎样连接

```text
resource_submission
具体实体、当前状态、专属参数、准入证据
              ↓
        资源能力适配器
              ↓
统一能力：功率、能量、时长、响应、爬坡、精度
              ↓
market_task + market_rule_parameters
任务要求、市场状态、准入阈值、规则版本
              ↓
        规则门控与最短板计算
              ↓
scoring_result
六项或单项结果、物理能力、状态、指数、短板、证据
```

三个接口都使用稳定标识、明确单位和证据状态。不得只传一个资源类别名称后直接查出固定分数。

## 3. 接口一：资源提交 `resource_submission`

机器校验文件：`config/resource_submission_schema.json`。

### 3.1 外层字段

| 字段 | 类型 | 必填 | 含义 |
| --- | --- | --- | --- |
| schema_version | string | 是 | 当前为 `1.0` |
| submission_id | string | 是 | 本次提交或更新的唯一编号 |
| submitted_at | date-time | 是 | 提交时间，带时区 |
| calculation_purpose | enum | 是 | `standard_profile`、`specific_task` 或 `both` |
| evidence_status | enum | 是 | `verified_entity_data`、`public_dataset`、`simulation_assumption`、`pending_verification` |
| entity | object | 是 | 实体身份、共性参数、专属参数和准入证据 |
| source_records | array | 是 | 数据来源记录；即使为构造数据也要说明构造目的 |

### 3.2 实体身份和共性字段

| 字段 | 单位/类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| entity_id | string | 是 | 具体场站、设备群或聚合单元的稳定编号 |
| entity_name | string | 是 | 便于人工识别的名称 |
| resource_type | enum | 是 | 当前 16 类之一；新增类别需先登记模型 |
| aggregation_id | string/null | 否 | 所属聚合单元；单体未聚合时为空 |
| region | string | 是 | 如 `CN-SD`，用于选择规则版本 |
| data_timestamp | date-time | 是 | 当前状态参数的观测时点 |
| rated_power_mw | number | 是 | 额定或核定功率，必须大于 0 |
| availability_pct | number | 是 | 当前可用率，范围 0—100 |
| response_time_s | number/null | 条件必填 | 端到端响应时间；仅有设备本体值时必须在来源说明中区分 |
| ramp_rate_mw_per_min | number/null | 条件必填 | 可验证的功率变化速率 |
| tracking_error_pct | number/null | 条件必填 | 有跟踪测试时填写；没有时为 null，不补 0 |
| specific_constraint_pass | boolean/null | 是 | 当前资源专属安全、品质或工艺约束是否通过；证据不足为 null |
| model_parameters | object | 是 | 该资源类别的专属物理参数 |
| market_qualification | object | 是 | 注册、计量、通信、控制、测试和绿电资格等证据 |

### 3.3 第一批资源专属参数

#### 分布式光伏

| 字段 | 单位 | 作用 |
| --- | --- | --- |
| current_power_mw | MW | 当前实际出力 |
| forecast_p10_mw | MW | 给定时域的保守预测下界 |
| forecast_horizon_h | h | 预测覆盖时长 |
| reserved_headroom_mw | MW | 已主动预留且可验证的上调空间 |
| curtailable_power_mw | MW | 可下调出力 |
| grid_connection_limit_mw | MW | 并网点功率限制 |
| green_eligible | boolean | 是否具备绿电供给资格证据 |

无预留、无配储时，光伏不得仅用“额定功率减当前功率”承诺上调，因为未来辐照未必支持该空间。

#### 储能

| 字段 | 单位 | 作用 |
| --- | --- | --- |
| energy_capacity_mwh | MWh | 当前可用口径下的能量容量 |
| soc | 0—1 | 当前荷电状态 |
| soc_min / soc_max | 0—1 | 允许运行安全边界 |
| soh | 0—1 | 健康状态；容量已按 SOH 修正时需注明 |
| charge_efficiency | 0—1 | 充电效率 |
| discharge_efficiency | 0—1 | 放电效率 |
| max_charge_power_mw | MW | 当前允许最大充电功率 |
| max_discharge_power_mw | MW | 当前允许最大放电功率 |

上、下调能力必须分别计算。SOC 变化后，可用能量和双向最短板应动态变化。

#### 充电桩（充电站）

| 字段 | 单位 | 作用 |
| --- | --- | --- |
| connected_power_mw | MW | 当前已连接车辆对应的可用设备功率 |
| current_power_mw | MW | 当前聚合充电功率 |
| min_power_mw / max_power_mw | MW | 本时点允许的充电功率边界 |
| flexible_energy_mwh | MWh | 在不破坏离站目标的前提下可移动电量 |
| earliest_departure_at | date-time | 当前控制窗口内最早离站时间 |
| target_energy_remaining_mwh | MWh | 完成用户目标尚需电量 |
| user_authorized | boolean | 是否获得调节授权 |
| v2g_enabled | boolean | 是否具备双向设备、并网和授权证据 |
| v2g_power_mw | MW | 经核验的可放电功率；未核验时填 0 并说明原因 |

### 3.4 其余 13 类资源的参数域

| 参数域 | 适用资源 | 关键字段方向 |
| --- | --- | --- |
| thermal_process | 蓄热锅炉、冷水机组、冷库、空调、烘干机 | 当前/最小/最大功率、温度或含水率边界、热缓冲能量、反弹、期限 |
| pump_process | 辅助泵、高压电机泵 | 当前/最小/最大功率、流量、压力、液位、VFD、离散启停许可、并联备用泵、联锁 |
| batch_process | 球磨机、中频电炉、电窑炉、搅拌机、压机 | 单元功率、当前阶段、可中断数量、可排程数量、库存、截止期、质量安全门槛 |
| compute_workload | 算力 | IT/设施功率、PUE、可延迟任务比例、可追加任务、队列电量、截止期、SLA和迁移条件 |

这些参数域不是默认数值表。每个实体仍需提交自己的数值和来源。

### 3.5 准入证据字段

`market_qualification` 至少保留以下布尔值或 null：

- `registered`：是否完成适用主体注册；
- `metering`：是否满足计量条件；
- `communication`：是否满足通信条件；
- `direct_control`：是否具备对应控制接口；
- `performance_test`：是否完成适用性能测试；
- `green_project_eligible`：供给侧绿色项目资格；
- `traceable`：绿色电量可追溯；
- `consumer_relation`：消费主体或代理关系证据；
- `green_contract`：绿电合同或任务证据；
- `consumer_metered`：消费侧计量证据。

不能确认时填 null。不得把未知写成 false，也不得把缺证据写成已通过。

## 4. 接口二：市场任务 `market_task`

机器校验文件：`config/market_task_schema.json`。

### 4.1 外层字段

| 字段 | 类型 | 必填 | 含义 |
| --- | --- | --- | --- |
| schema_version | string | 是 | 当前为 `1.0` |
| task_id | string | 是 | 任务或比较场景唯一编号 |
| calculation_mode | enum | 是 | `standard_benchmark` 或 `specific_task` |
| market_output | enum | 是 | 六项输出之一 |
| region | string | 是 | 规则适用地区 |
| valid_from / valid_to | date-time/null | 是 | 任务时间窗口；标准场景可为空 |
| evidence_status | enum | 是 | 规则、真实任务、公开数据、模拟假设或待核验 |
| requirements | object | 是 | 该任务所需的物理和性能指标 |
| source_records | array | 是 | 正式规则、调度指令或构造说明 |

### 4.2 任务要求字段

| 字段 | 单位/类型 | 使用场景 |
| --- | --- | --- |
| direction | enum | `up`、`down`、`bidirectional`、`supply`、`shift` |
| required_power_mw | MW | 具体任务的绝对功率要求 |
| required_power_ratio | 0—1 | 标准场景按实体额定功率定义的相对要求 |
| required_energy_mwh | MWh | 具体任务的绝对能量要求 |
| required_energy_ratio | 0—1 | 标准绿电场景的相对能量要求 |
| required_duration_h | h | 必须持续的时间 |
| max_response_time_s | s | 最大允许响应时间 |
| required_ramp_mw_per_min | MW/min | 具体任务的最小爬坡率 |
| required_ramp_ratio_per_min | 1/min | 标准场景相对额定功率的爬坡要求 |
| max_tracking_error_pct | % | 最大跟踪误差 |
| contract_energy_mwh | MWh | 绿电合同电量 |
| eligible_generation_energy_mwh | MWh | 合格发电量 |
| user_consumption_energy_mwh | MWh | 用户消费电量 |

`specific_task` 应优先使用带物理单位的绝对要求。`standard_benchmark` 可以使用比例要求，但必须标记为比较假设，不得伪装成正式市场阈值。

## 5. 接口三：评分结果 `scoring_result`

机器校验文件：`config/scoring_result_schema.json`。

### 5.1 一行代表什么

一行只代表：一个具体实体，在一个明确场景下，对一项市场输出的计算结果。

同一实体的六项标准画像应生成六行。一次具体调频任务通常生成一行；若一次任务同时包含多个市场目标，则每项市场分别生成一行，并通过同一个 `task_id` 关联。

### 5.2 结果字段

| 字段组 | 字段 | 说明 |
| --- | --- | --- |
| 追踪 | result_id、calculated_at、engine_version | 唯一结果和程序版本 |
| 对象 | submission_id、entity_id、resource_type、aggregation_id | 对应资源 |
| 场景 | task_id、calculation_mode、market_output、region | 对应任务 |
| 能力 | available_up_power_mw、available_down_power_mw、available_up_energy_mwh、available_down_energy_mwh、duration_h、response_time_s、ramp_rate_mw_per_min、tracking_error_pct | 带单位的物理结果 |
| 门控 | market_status、admission_status、specific_constraint_status | 市场、准入和资源专属约束分开 |
| 比较 | metric_ratios、bottleneck_metric、feasibility | 单项满足率和最短板 |
| 指数 | diagnostic_scenario_fit_index、benchmark_fit_index、formal_scenario_fit_index | 调试、标准比较与正式指数分开 |
| 数据 | evidence_status、data_completeness_pct、missing_fields、evaluated_rule_ids、failed_rule_ids | 证据、缺失和规则追踪 |
| 解释 | explanation | 面向人工复核的简短原因 |

### 5.3 状态值

| 字段 | 可用状态 |
| --- | --- |
| market_status | `operational`、`planned`、`not_open`、`unknown` |
| admission_status | `pass`、`fail`、`pending_evidence`、`not_applicable` |
| specific_constraint_status | `pass`、`fail`、`pending_evidence` |
| feasibility | `feasible`、`not_feasible`、`not_computable`、`not_applicable` |

### 5.4 两个指数不可混用

- `diagnostic_scenario_fit_index`：只要物理输入和任务要求足以计算，就可用于程序调试、模拟任务或敏感性分析；不能作为正式结论。
- `benchmark_fit_index`：标准比较场景下可为 0—100；必须同时保留 `simulation_assumption` 或相应证据标签。具体任务模式下为 `not_applicable`。
- `formal_scenario_fit_index`：只有市场开放、准入通过、专属约束通过、任务明确且证据足够时才是 0—100；其他情况为字符串 `not_computable`。

备用在山东正式市场规则发布前，`formal_scenario_fit_index` 必须为 `not_computable`。可以输出物理能力和 `reserve_readiness` 的比较结果，但必须显示市场状态。

## 6. 缺失值和零值规则

- `0` 表示已经测量或计算，结果确实为零。
- `null` 表示输入不存在、未知或当前不适用，必须结合状态字段解释。
- `not_computable` 表示由于市场、规则、任务或证据条件不足，正式结果不能计算。
- `not_applicable` 表示该输出不适用于该实体，例如普通消费负荷的绿电供给侧结果。
- 禁止把 null 自动填成 0，也禁止用 0 分代替准入失败、市场未开放或证据不足。

## 7. 版本和更新规则

- 三个接口都使用 `schema_version`；不兼容变更提升主版本。
- 资源能力模型、评分引擎和规则库分别保存版本，便于重现历史结果。
- 规则参数继续存放在 `config/market_rule_parameters.csv`，不复制到资源实体文件。
- 标准场景是可更新配置，任何参数变化都应改变场景版本并重新生成结果。
- 原始提交保留不动。清洗、单位转换和派生能力记录在处理中间结果或日志中。

## 8. 第一批实现验收条件

光伏、储能和充电桩接入统一程序后，至少通过以下检查：

1. 三类资源提交均能通过结构校验，缺必填项时给出明确字段名。
2. 每个实体均可生成六项标准场景记录，不适用项明确显示 `not_applicable`。
3. 输入同一储能实体，只改变 SOC，相关能量、最短板和指数随之变化。
4. 输入同一实体，只改变任务功率或持续时间，结果随任务变化。
5. 市场未开放、准入失败和证据不足不会显示成正式 0 分。
6. 每条结果能够追溯到资源提交、任务、规则版本和引擎版本。
7. 现有规则边界测试接入统一程序后仍应通过。

## 9. 下一步

以这三个接口为边界，建立统一评分程序骨架，并首先实现分布式光伏、储能和充电桩三个资源能力适配器。随后使用标准六项画像和储能 SOC 变化的具体调频任务完成第一轮动态重算演示。
