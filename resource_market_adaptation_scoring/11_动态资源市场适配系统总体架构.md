## 2. 一句话目标

系统接收一个具体资源实体或聚合单元的参数，先按其资源类型计算可解释的物理调节能力，再结合市场状态、准入规则和明确任务要求，动态生成现货、调频、备用、爬坡、绿电供给侧和绿电消费侧六项结果。

16 类资源是首版模型库，不是 16 个永久不变的分数。实体参数、运行状态、市场规则或任务要求发生变化时，结果必须能够重新计算；未来新增资源也应通过增加资源适配器接入同一流程。

## 3. 当前阶段与前一阶段的衔接

当前没有更换研究主线。项目仍是“16 类资源特性建模—五类市场关联评分—专利交底书”。工作阶段从算法论证转入系统化实现。

```text
        ↓

```

`10_算法评测方案与第一轮规则基准结果.md` 完成的是评分核心的逻辑测试：它检查硬门槛、缺失证据和最短板处理是否按设计运行。336 条构造案例和 24 条山东规则临界值测试不能证明系统已经完成，也不能证明真实场景精度达到 90%。它们在完整系统中属于“规则回归测试与边界测试”。

因此，后续实现必须复用已经评测过的规则门控和最短板原则，不能另起一套与评测无关的固定加权评分。

## 4. 系统面向的三个对象

### 4.1 类别模型

类别模型描述某一类资源需要采集哪些参数、采用什么物理关系、有哪些专属约束。它只提供计算模板和有来源的参数范围，不直接输出该类资源的固定市场分数。

首版包括 PPT v9 确定的 16 类资源：分布式光伏、蓄热锅炉、冷水机组、冷库、辅助泵类、高压电机泵、空调、充电桩（充电站）、水泥（球磨机）、中频电炉、电窑炉、储能、算力、搅拌机、烘干机（热泵）、压机（液压/油压/水压）。

### 4.2 具体资源实体

具体实体是某个厂商、场站、设备群或聚合单元。它拥有自己的额定功率、实时状态、可用能量、响应时间、生产约束、控制与计量条件以及证据来源。

老师在会议中提到“具体的某个实体、某个厂家、某个光伏厂来了以后，可以算具体的值”，对应的就是这一层。系统的动态计算主要发生在实体层。

### 4.3 市场任务或比较场景

市场任务说明本次需要资源完成什么，例如调节方向、功率、持续时间、响应时间、爬坡要求和跟踪精度。没有任务要求，就无法判断一个资源是否“足够完成这次任务”。

为了在没有真实指令时也能调试系统，可以使用明确标注的“标准比较场景”。比较场景只用于形成动态画像和横向检查，不等同于山东正式市场任务或真实交易资格。

## 5. 两种使用入口

### 5.1 入口 A：标准六项画像

用途：新资源首次提交、资源档案更新、方案比较和系统演示。

输入：具体实体参数、证据状态，以及一套可更新的标准比较场景。

输出：同一实体的六项结果，包括物理能力、规则状态、单项满足率、最短板和比较场景指数。

这里的 0—100 结果必须命名为“标准场景适配指数”或“比较场景指数”，不得写成正式市场评分。标准场景改变后结果也会改变。

### 5.2 入口 B：具体任务核验

用途：判断某个资源或聚合组合能否完成一项明确的市场任务。

输入：实体实时参数、正式市场规则和一条具体任务要求。

输出：任务可行性、可承诺物理量、各项满足率、最短板、场景适配指数和证据状态。

只有市场已开放、准入证据完整、任务要求明确且输入具有可追溯依据时，才允许生成正式场景适配指数。否则正式结果为 `not_computable`，可以另行展示带有清楚标签的模拟或准备度结果。

## 6. 总体计算架构

```text
资源提交层
  ├─ 实体身份与资源类型
  ├─ 共性参数
  ├─ 资源专属参数
  ├─ 实时运行状态
  └─ 数据来源与证据状态
          ↓
数据校验层
  ├─ 必填项检查
  ├─ 单位和方向统一
  ├─ 时间戳与有效期检查
  ├─ 合理边界检查
  └─ 缺失项显式标记
          ↓
资源能力适配层
  ├─ 识别资源类别模型
  ├─ 应用资源专属物理约束
  └─ 转换为统一能力接口
          ↓
统一能力域
  ├─ 上调/下调功率（MW）
  ├─ 上调/下调能量（MWh）
  ├─ 可持续时间（h）
  ├─ 响应时间（s）
  ├─ 爬坡率（MW/min）
  ├─ 跟踪误差（%）
  ├─ 可用率（%）
  └─ 绿电供给或负荷转移能力
          ↓
市场规则与任务层
  ├─ 市场是否开放
  ├─ 主体和聚合单元准入
  ├─ 计量、通信、控制、测试条件
  ├─ 具体市场任务要求
  └─ 规则版本、地区和有效期
          ↓
评分与判定层
  ├─ 规则门控
  ├─ 能力/需求单项比值
  ├─ 最短板识别
  ├─ 场景适配指数
  └─ 多市场容量冲突检查
          ↓
结果层
  ├─ 六项市场结果
  ├─ 物理能力和单位
  ├─ 市场/准入状态
  ├─ 最短板及原因
  ├─ 数据完整度和证据状态
  └─ 经济结果（独立计算）
```

## 7. 资源差异如何进入统一系统

统一接口不表示 16 类资源使用相同的原始特征。各类资源先通过自己的适配器计算能力，再进入相同的市场比较程序。

| 资源模型族 | 典型资源 | 必须体现的专属约束 | 统一输出示例 |
| --- | --- | --- | --- |
| 发电预测型 | 分布式光伏 | 辐照与预测下界、限发、预留出力、并网条件 | 可承诺发电量、上下调功率、预测风险 |
| 储能状态型 | 储能 | SOC、SOH、安全边界、效率、循环限制 | 双向功率、双向能量、持续时间 |
| 热惯性负荷型 | 锅炉、冷机、冷库、空调、热泵烘干 | 温度、热负荷、蓄热/蓄冷、舒适或品质边界、反弹 | 可降/增负荷、热缓冲支持时间 |
| 泵与流程负荷型 | 辅助泵、高压电机泵 | 液位、流量、压力、变频、启停和工艺联锁 | 连续或离散调节能力、可持续时间 |
| 车辆连接型 | 充电桩 | 连接状态、到离站时间、目标 SOC、用户授权、V2G | 可延迟/增加充电功率、可移电量 |
| 批次生产型 | 球磨机、电炉、窑炉、搅拌机、压机 | 当前工序、批次可中断性、库存、期限、质量与安全 | 可移批次功率、离散调节量、窗口 |
| 任务调度型 | 算力 | 实时/批处理任务、截止期、SLA、积压和迁移 | 可延迟功率、可转移电量、恢复约束 |

新增资源时，只需新增类别字段定义和能力适配器，并复用后面的规则门控、任务比较和结果输出模块。

## 8. 六项结果的统一口径

| 输出 | 核心问题 | 特别约束 |
| --- | --- | --- |
| 现货适配 | 能否在指定时段提供约定的电力和电量 | 主体准入、方向、持续时间、可用容量 |
| 调频适配 | 能否连续、快速、准确地双向跟踪指令 | 双向能力、响应、爬坡、跟踪误差、性能测试 |
| 备用准备度 | 若山东未来组织备用市场，当前能力准备到什么程度 | 山东未正式开放，不能输出正式交易资格或收益 |
| 爬坡适配 | 能否在规定时间内提供持续的斜率和容量 | 功率、能量、响应和爬坡能力共同约束 |
| 绿电供给侧适配 | 是否能形成可追溯的合格绿电供给 | 项目资格、发电预测、计量和合同履约 |
| 绿电消费侧适配 | 是否具备交易履约和向绿电充裕时段转移负荷的能力 | 交易履约与消纳协同分开，不能把移荷直接等同于绿色环境价值 |

六项结果并列展示，不合成为固定资源总分。不同市场解决的问题不同，跨市场加总会掩盖资源的真实专长和短板。

## 9. 场景最短板指数

对于任务要求中的每个必要指标，计算：

```text
单项满足率 = 可用能力 ÷ 任务要求
```

响应时间、跟踪误差等“越小越好”的指标使用反向比值。场景指数取所有必要指标满足率中的最小值，并限制在 0—100 范围内：

```text
场景适配指数 = 100 × min(各必要指标满足率)，上限为100
```

该指数回答的是“当前实体对当前任务的最短板满足程度”，不是资源类别的固定质量分。资源参数或任务要求改变，指数随之改变。

规则门控优先于指数：市场未开放、主体不具备准入条件或关键证据缺失时，正式指数显示 `not_computable`，同时保留物理能力和具体原因。准入失败不能用 0 分替代，因为 0 分会混淆“没有能力”和“当前不允许计算”两种情况。

## 10. 输出记录结构

正式结果采用“一条实体—一个场景—一项市场输出一行”的长表结构。至少保留以下字段：

| 字段组 | 主要字段 |
| --- | --- |
| 身份 | entity_id、resource_type、aggregation_id |
| 场景 | calculation_mode、scenario_id、market_output、task_timestamp |
| 能力 | available_power_mw、available_energy_mwh、duration_h、response_time_s、ramp_rate_mw_per_min、tracking_error_pct |
| 判定 | market_status、admission_status、feasibility、bottleneck |
| 指数 | benchmark_fit_index 或 formal_scenario_fit_index |
| 证据 | evidence_type、source_id、verified_at、data_completeness |
| 解释 | failed_rule_ids、missing_fields、constraint_notes |

真实数据、规则数据、文献数据和构造数据必须分开标记。构造数据允许用于跑通流程、边界测试和敏感性分析，但不能包装成真实项目结果。

## 11. 系统验证框架

系统效果不能只看一个“准确率”。应按层验证：

| 验证层 | 要回答的问题 | 当前状态 |
| --- | --- | --- |
| 规则单元测试 | 阈值、状态和缺失处理是否正确 | 已完成第一轮 |
| 资源物理模型测试 | 各类资源能力计算是否符合物理和工艺约束 | 待逐类接入 |
| 动态重算测试 | 参数或任务变化后结果是否按规律变化 | 待统一程序实现 |
| 任务回放测试 | 用同一主体的指令与响应能否正确预测履约 | 缺真实配对数据 |
| 外部对比测试 | 相比容量法、等权法是否降低误判并改善能力预测 | 构造基准已完成，真实验证待补 |
| 验收精度测试 | 可调容量与响应能力模型是否达到不低于 90% 的约定指标 | 评价对象和真实数据到位后执行 |

其中“90%”不能直接沿用构造规则测试的 100%。后续应分别明确容量预测误差、响应判定准确率或履约预测准确率的评价口径。

## 13. 后续实施顺序

后续必须按以下顺序推进，避免再次从框架直接跳入细节：

1. 审阅并确认本总体架构。
2. 定义统一资源提交模板、任务模板和结果数据字典。
3. 建立统一能力接口，先接入光伏、储能和充电桩三类已有基础模型。
4. 跑通标准六项画像和具体任务核验两个入口，并完成动态重算测试。
5. 将其余 13 类资源按模型族分批接入，每接入一类就增加专属约束测试。
6. 把现有规则基准评测改造成统一程序的自动回归测试。
7. 使用公开数据做外部流程校验；获得同一主体任务—响应数据后开展真实效果验证。
8. 在系统结构和权利要求边界稳定后编写专利交底书。

## 14. 当前明确不做的事情

- 不恢复 PPT 中人工设置的先验分值。
- 不形成 16 类资源固定得分表。
- 不采用 H/M/L 人工重要度或未经依据的市场权重。
- 不把六项市场结果合成跨市场总分。
- 不用外省备用规则冒充山东规则。
- 不把标准比较场景指数称为正式市场评分。
- 不把构造数据、公开异源数据试算或规则逻辑正确率称为真实项目精度。
- 不在总体架构未确认前继续批量扩展资源细节或外围调研。
