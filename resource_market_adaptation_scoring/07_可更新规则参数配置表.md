# 可更新规则参数配置表说明

> 文档状态：2026-09-10 第一版  
> 机器可读配置：[market_rule_parameters.csv](config/market_rule_parameters.csv)  
> 当前用途：把会变化的市场状态、准入阈值、报价边界和结算公式从算法代码中分离，后续更新规则时无需改写核心算法。

## 1. 配置范围

当前配置表只保存**市场规则参数和规则状态**，不保存三类容易混淆的数据：

| 数据层 | 是否放入本表 | 保存位置与原则 |
|---|---|---|
| 市场规则状态、准入阈值、报价边界、规则公式 | 是 | 本配置表；每条必须带适用地区、对象、时间和正式来源 |
| 具体资源实体参数 | 否 | 后续实体输入表；以设备资料、实测或经核验数据为准 |
| 场景任务参数 | 否 | 每次计算的场景输入；模拟值必须标为 `simulation_only` |
| 文献中的资源典型范围 | 否 | 资源证据库；作为缺项提示、范围核查或模拟边界，不代替实体实测值 |
| 算法方法选择 | 否 | 算法文档和程序配置；当前采用“关键满足率取最小值”，不设人工权重 |

## 3. 配置表字段

| 字段 | 含义 | 更新要求 |
|---|---|---|
| `parameter_id` | 稳定参数编号 | 算法按此编号读取；含义不变时不要随意改名 |
| `record_version` | 同一参数的记录版本 | 新规则替代旧规则时新增版本，不覆盖旧记录 |
| `market_output` | 适用市场或输出 | 可填一个或多个输出，多个用 `|` 分隔 |
| `parameter_name_cn` | 中文名称 | 面向审阅者说明参数含义 |
| `parameter_type` | `status/numeric/integer/formula` 等 | 决定算法如何解释 `value` |
| `operator` | 比较或运算符 | 如 `>=`、`range`、`formula`；状态类填 `=` |
| `value` | 参数值 | 待正式规则确定时必须留空，不得经验补值 |
| `unit` | 单位 | 数值参数必填，状态和公式可填 `none` 或相应结果单位 |
| `region` | 适用地区 | 国家规则填 `CN`，山东规则填 `CN-SD` |
| `applicable_object` | 适用主体或交易对象 | 防止把储能阈值套用到所有资源 |
| `source_level` | 国家规则、地方规则等 | 冲突时执行“用户最新决定 > 可研 > 国家规则 > 山东具体实施规则”的项目判断；同一市场技术参数通常以有效且更具体的山东规则执行 |
| `source_document/source_url/source_clause` | 正式依据 | 条款未精确定位时标 `to_locate`，正式使用前补齐 |
| `effective_from/effective_to` | 生效区间 | 历史计算按计算日期选择当时有效版本 |
| `record_status` | `active/recheck_before_use/pending_rule/external_reference_only/expired` | 算法只自动采用适用日期内的 `active` 记录；外省参考和其他状态不得自动替代山东规则 |
| `last_verified/next_review` | 最近核验和下次复核日期 | 价格、门槛和市场状态需要定期复核 |
| `missing_action` | 缺失或失效时处理 | 原则上输出 `not_computable`、`pending_evidence` 或人工复核，不回填经验值 |

## 4. 更新规则

1. 发现新规则时，先核对发布机关、文号、发布日期、生效日期、适用地区和适用主体。
2. 旧参数已经参与过计算时不直接覆盖：将旧记录标为 `expired` 并填写 `effective_to`，再新增一个 `record_version`。
3. 同一参数存在国家原则和山东具体阈值时，两条都保留；算法按地区、对象、日期选择更具体且有效的实施参数。
4. `recheck_before_use` 表示该值有正式来源，但可能已被后续文件调整；正式计算前必须再次核验。
5. `pending_rule` 的值保持为空。备用市场当前的响应时间、持续时长、最小申报容量和价格上限均采用这一状态。
6. 模拟数据、论文典型值和专家判断不得写成 `official_rule`，也不得用于替换尚未发布的市场规则阈值。
7. 每次算法输出应记录实际使用的 `parameter_id + record_version`，保证结果可以追溯和复现。
8. `external_reference_only` 只允许用于明确标注地区的对照或压力测试，不能被山东正式计算自动选中。

## 5. 算法读取方式

后续程序更新时采用以下顺序：

1. 按 `market_output` 选择参数；
2. 按计算日期筛选 `effective_from/effective_to`；
3. 按 `region` 和 `applicable_object` 匹配适用记录；
4. 只自动应用 `record_status=active` 的数值或公式；
5. 对 `recheck_before_use` 发出复核提示；
6. 对 `pending_rule`、参数缺失或适用对象不明的情况输出 `not_computable` 或 `pending_evidence`；
7. 将命中的配置版本写入结果文件。
