# 评分方法比较与第一版候选算法

> 文档状态：2026-09-10 审阅修订版  
> 上游依据：`01_十六类资源特征清单.md`、`02_五类市场需求属性.md`、`03_资源特征与市场需求映射表.md`  
> 当前定位：定义可运行、可解释、可扩展并可进一步凝练为专利步骤的第一版算法。  
> 重要边界：不使用 PPT 人工分值，不使用 H/M/L，不设置固定资源总分，不用人工权重掩盖市场门槛或资源短板。

## 1. 本次审阅结论

原候选算法中的以下内容不再采用：

1. 不采用“人工设置市场权重后加权求和”作为核心算法。
2. 不采用 `实体值×可信度 + 类别值×剩余比例`。这种计算会合成一个未经观测的参数。
3. 不采用 `适配分×置信度`。适配能力和数据完整度含义不同，必须分别输出。
4. 不为 16 类资源设置永久不变的类别分数。
5. 不把六项市场结果合成一个固定“资源总分”。不同市场的商品、时间尺度和业务目标不同，跨市场总分只能是特定项目下的临时决策结果。
6. 不把价格和收益混入技术适配指数。市场价格变化只影响经济结果，不应改变设备的物理能力。

第一版主算法改为：

**基于规则门控、约束能力域与场景最短板指数的虚拟电厂资源—市场适配方法。**

名称仍为候选，后续撰写专利交底书时再根据查新和权利要求范围调整。

## 2. 算法要解决的问题

对某个具体资源实体或虚拟电厂聚合单元，给定市场、方向、时段和服务任务后，算法回答：

1. 当前市场是否已经运行；
2. 聚合单元是否满足正式准入条件；
3. 资源能够提供多少真实物理能力；
4. 对指定任务能否履约，最薄弱的条件是什么；
5. 单独参加一个市场时的最大能力是多少；
6. 同时参加多个市场时，容量和电量如何避免重复占用；
7. 结论有多少真实数据支撑，哪些参数仍待补齐；
8. 在技术可行的基础上，预计收入、成本和风险是多少。

## 3. 为什么不再使用简单加权总分

| 方法 | 本项目判断 | 使用位置 |
| --- | --- | --- |
| 简单加权评分 | 容易让容量优势抵消响应、控制或准入短板；权重缺乏客观依据 | 不作为主算法；仅可在未来特定项目决策中使用经确认的临时偏好 |
| AHP | 可以整理专家偏好，但不能把偏好变成法规或真实能力 | 不用于当前适配指数；可用于未来项目方案选择 |
| TOPSIS | 排名依赖同批候选对象，新增资源可能改变旧资源结果 | 只作为论文对比方法 |
| 模糊综合评价 | 可以表达模糊边界，但隶属函数仍需规则或数据依据 | 有可靠边界后可作为局部转换函数，不作第一版骨架 |
| 灰色关联 | 适合小样本关系比较，但关联度不等于准入或履约能力 | 只作为论文对比方法 |
| 数据驱动学习 | 可从真实履约记录学习非线性关系 | 真实数据到位后的校准和验证模块 |
| 规则约束与能力域 | 能保留法规门控、物理单位、方向、时间和资源专属约束 | 第一版核心能力计算 |
| 场景最短板指数 | 不需要人工权重，能够直接暴露不满足任务的关键指标 | 第一版辅助展示指数 |
| 多市场约束优化 | 能处理容量、电量、方向、恢复和时段冲突 | 同时参与多市场的能力分配模块 |

## 4. 评分对象与输出层次

### 4.1 两层对象

| 对象 | 输入 | 核心输出 |
| --- | --- | --- |
| 资源实体/资源类别 | 设备、场站或类别的物理参数、状态和专属约束 | 带方向、时段和证据的能力域 |
| 虚拟电厂聚合单元 | 所含实体能力、聚合关系、网络与控制、市场注册和历史履约 | 门控状态、可信聚合能力、可申报量和场景适配结果 |

类别层只保存带来源和适用条件的参数区间，不形成固定类别分。0—100 指数原则上用于“具体实体或聚合单元—具体市场任务”的计算。

### 4.2 六项结果，不设固定资源总分

- `spot_fit`
- `frequency_fit`
- `reserve_readiness`
- `ramping_fit`
- `green_supply_fit`
- `green_consumption_fit`
  - `transaction_compliance`：交易履约适配；
  - `absorption_synergy`：绿电消纳协同，不直接代表交易资格或收益。

六项结果分别展示，不设置跨市场固定权重。如果未来需要筛选优先接入资源，可针对当时明确的业务目标另建“项目决策分”，并单独记录目标、权重、使用期限和批准人；该决策分不是资源固有属性，也不属于本算法的基本输出。

### 4.3 “适配度—敏感性—分类—分级”正式定义

| 概念 | 正式定义 | 计算对象与条件 | 当前输出 |
| --- | --- | --- | --- |
| 市场适配度 | 具体实体或聚合单元对一项明确市场任务的规则和能力满足程度 | 必须绑定市场、方向、时段、任务要求、规则版本和实体数据 | 六项结果分别输出门控、物理能力和 `scenario_fit_index`；不合成资源总分 |
| 敏感性 | 在合法物理范围和证据范围内改变某个输入参数，观察能力、适配指数、最短板或准入结果的变化 | 必须记录基准场景、扰动参数、扰动范围和来源 | 变化方向、变化幅度、瓶颈是否切换、门控是否变化；不把敏感性当作适配度同义词 |
| 资源分类 | 根据可核验的资源角色、调节机理、控制方式和约束类型赋予一个或多个功能标签 | 标签由资源参数和配置事实触发，一项资源允许多标签 | 功能标签及依据；不输出固定类别优劣 |
| 资源分级 | 在特定市场和评价方案内，依据正式规则阈值、明确任务要求或真实履约分布划分等级 | 必须保存市场、场景、分级边界、数据范围、版本和有效期 | 当前无可靠分级边界时输出 `not_graded`，不得人工设置优/良/中/差 |

四者的关系为：

```text
资源分类说明“它属于什么能力角色”
→ 市场适配度说明“它对这项任务能否满足、短板是什么”
→ 敏感性说明“哪些参数变化会改变结果”
→ 资源分级在具备正式边界后说明“它在该市场和场景下属于哪一级”
```

### 4.4 功能分类标签

当前分类采用多标签，不强迫一个资源只能属于一类：

| 标签维度 | 候选标签 | 判定依据 |
| --- | --- | --- |
| 市场角色 | 绿色电源、储能、柔性负荷 | 项目资格、能量边界和资源物理属性 |
| 调节机理 | 连续功率调节、分档调节、离散启停、时段平移、充放电双向、组合履约协同 | 控制方式、功率曲线、能量状态及专属约束 |
| 控制方式 | 调度直控、聚合自动控制、本地自动控制、人工控制 | 控制系统、通信和测试证据 |
| 主要约束 | 能量约束、热惯性/温度约束、库存约束、批次/工艺约束、用户行为约束、网络/站级约束 | SOC、温度、库存、工序、授权、网络容量等实体字段 |
| 绿电作用 | 绿电供给、交易履约、绿电消纳协同 | 绿色项目资格、合同与追溯关系、可转移用电能力 |

“快速连续调节”“长时移峰”等带程度的标签必须附带适用任务阈值。例如只有在明确任务要求下验证响应时间达标，才能标为“对该任务快速”；不得给整类资源永久贴上无阈值的“快速”或“长时”标签。

### 4.5 敏感性分析

对参数 `x_k` 在有依据的扰动范围 `[x_k^-, x_k^+]` 内重新运行能力、门控和场景适配计算：

```text
sensitivity_result(k) = {
  baseline_result,
  perturbed_result_lower,
  perturbed_result_upper,
  change_direction,
  index_change_interval,
  bottleneck_switch,
  gate_status_change,
  perturbation_source
}
```

扰动范围优先来自测量误差、实体历史波动、标准测试范围或可比论文证据；没有依据时不自行采用固定 ±5% 或 ±10%。由于最短板函数可能发生拐点或瓶颈切换，第一版采用有限扰动重算，不假设结果必然线性或可微。

### 4.6 每项市场结果的标准输出

```text
market_result = {
  market_status,
  gate_status,
  physical_capability,
  credible_offer_capability,
  scenario_fit_index,
  bottleneck,
  missing_required_fields,
  data_completeness,
  evidence_sources,
  rule_version,
  economic_result_reference
}
```

## 5. 输入数据结构

### 5.1 资源实体输入

- 额定值、当前功率和计量边界；
- 上/下调能力和方向；
- 可用电量和持续时间；
- 响应时间、爬坡率和跟踪误差；
- 在线状态和可用时段；
- SOC、温度、库存、工序、车辆停留、任务期限等专属约束；
- 通信、控制和用户授权；
- 历史履约与数据质量；
- 绿色项目、电量和追溯信息。

### 5.2 市场任务输入

0—100 场景适配指数必须绑定明确任务，至少包括：

```text
scenario = {
  market,
  direction,
  start_time,
  duration,
  required_power_or_energy,
  response_limit,
  ramp_requirement,
  tracking_limit,
  availability_requirement,
  applicable_rule_version,
  scenario_source
}
```

`scenario_source` 只允许：

- `actual_market_order`：真实市场交易或调度任务；
- `official_threshold`：正式规则规定的最低条件；
- `verified_test_protocol`：正式测试或标准场景；
- `research_case`：有明确来源的论文场景；
- `simulation_assumption`：明确标注的模拟任务。

模拟任务可以用于算法演示，不能写成现实市场要求或项目实测结果。

### 5.3 市场和规则输入

- 市场运行状态；
- 主体和聚合关系要求；
- 计量、通信、数据报送和控制条件；
- 测试及性能要求；
- 最小申报量、持续时间、价格和结算规则；
- 规则文件、条款、地区、生效和失效日期。

## 6. 总体计算流程

```text
步骤 S1：读取规则版本和市场运行状态
步骤 S2：读取实体参数；类别资料只作有条件的范围参考
步骤 S3：按资源专属约束计算实体能力域
步骤 S4：在共同时间窗内进行聚合和可信能力折算
步骤 S5：执行聚合单元市场准入门控
步骤 S6：将可信能力与明确市场任务逐项比较
步骤 S7：输出场景适配指数、短板、物理量和数据完整度
步骤 S8：分别计算单市场独立能力和多市场同时可行域
步骤 S9：在技术可行域内单独进行经济测算
```

## 7. 步骤 S1：市场状态与规则版本

市场状态取值：

```text
operational
trial_or_settlement_test
planned
not_applicable
```

山东备用当前记为 `planned`。此时可以计算备用物理能力和模拟任务下的准备度指数，但准入状态固定输出 `not_open`，不得输出已经入市或确定收益。

规则参数使用顺序：

```text
国家现行规则确定上位框架
→ 山东现行规则补充当地执行参数
→ 国家/行业标准和正式测试协议补充技术定义
→ 同行评审论文补充有条件的案例范围
→ 其他可核验渠道补缺
```

若山东细则与国家规则不存在冲突，采用山东更具体的执行参数；若发生冲突，以国家规则为准并记录差异。

## 8. 步骤 S2—S3：实体取值与约束能力域

### 8.1 不再混合实体值和类别值

同一字段按以下顺序选择：

1. 现场测试或端到端响应日志；
2. SCADA/BMS/EMS/MES/充电平台等真实运行数据；
3. 验收报告、铭牌和厂商正式资料；
4. 同亚类、同规模、同工况的标准或文献案例范围；
5. 无可靠依据则保持 `null/待补齐`。

不同来源不做线性混合。类别资料只能形成条件区间、验证边界或模拟样例，不能自动填成实体实测值。

### 8.2 实体能力域

对资源实体 `i`、时刻 `t` 和连续服务时间 `h`，计算：

```text
C_i(t,h) = {
  p_up_available_i(t,h),
  p_down_available_i(t,h),
  e_up_available_i(t,h),
  e_down_available_i(t,h),
  response_time_i,
  ramp_up_i,
  ramp_down_i,
  tracking_error_i,
  recovery_i,
  availability_i,
  applicable_constraints_i
}
```

能力由当前状态和专属约束决定。例如：

- 储能由功率、SOC、可用能量、效率、温度和预留共同约束；
- 空调由在线台数、室温裕度、用户退出和恢复反弹约束；
- 充电站由车辆连接、离站时间、目标 SOC、用户授权和站级容量约束；
- 工业批次负荷由当前工序、库存、质量窗口和完工期限约束；
- 光伏由实时可用功率、预测区间、限发预留和配储状态约束。

如果输入是区间，能力输出也保持区间，不先取人为中值。

## 9. 步骤 S4：聚合与可信能力折算

### 9.1 聚合不是额定功率求和

聚合单元 `a` 的能力由所有实体在共同时间窗内的可行能力合成，并同时满足：

- 实体在线和授权状态；
- 调节方向一致性；
- SOC、温度、库存和生产约束；
- 用户舒适度、SLA和离站需求；
- 站级、馈线或聚合控制上限；
- 响应、通信和控制条件；
- 预测误差和历史履约安全裕度；
- 已承诺市场任务和调用后的恢复影响。

结构表达为：

```text
C_agg(t,h) = FeasibleAggregate(C_1, C_2, ..., C_n | constraints)
```

### 9.2 安全裕度

安全裕度优先由预测误差分布、历史履约分位数或正式规则确定。没有数据时输出能力区间和待验证状态，不人工填写统一折减系数。

可使用分位数形成可信能力，例如：

```text
p_credible(t,h,α) = 能力随机分布在给定可靠水平 α 下的保守分位值
```

其中 `α` 必须由真实市场要求、风险策略或明确测试方案给定，并与结果一起展示；不能隐藏为永久常数。

## 10. 步骤 S5：市场准入门控

```text
gate_status ∈ {pass, fail, pending_evidence, not_open}
```

- `pass`：适用的主体、聚合、计量、控制、测试和申报条件均已取得证据；
- `fail`：至少一项适用硬条件明确不满足；
- `pending_evidence`：关键材料或测试记录缺失；
- `not_open`：本地市场尚未正式组织。

门控结果不参加加权计算：

```text
if gate_status == fail:
    不形成正式可申报结果，列出未通过条件
elif gate_status == pending_evidence:
    输出物理能力和待核验项，不声称已经准入
elif gate_status == not_open:
    输出能力与准备度，不输出正式准入和收益
else:
    进入市场任务适配计算
```

### 10.1 门控异常时的显示规则

`fail`、`pending_evidence` 和 `not_open` 均不得在正式结果中显示为 `0 分`，因为市场资格状态不等于资源物理能力为零：

| 门控状态 | 物理能力 | 正式场景适配指数 | 研究性试算 |
| --- | --- | --- | --- |
| `pass` | 正常输出 | 关键数据和任务要求齐全时计算 | 可用于对照 |
| `fail` | 仍可输出 | `not_computable`，同时列出未通过条件 | 可选，必须标注“不代表已准入” |
| `pending_evidence` | 输出已有证据支持的能力或区间 | `not_computable` | 可选，明确缺失字段和假设 |
| `not_open` | 输出物理能力和准备度 | `not_computable` | 可按正式测试、论文或模拟任务计算准备度指数 |

程序内部也不得用数值 `0` 代替上述状态。状态、能力和指数应采用不同字段保存，避免后续统计或展示时把“没有资格/无法计算”误判为“能力为零”。

## 11. 步骤 S6—S7：场景适配指数

### 11.1 指数的定义

`scenario_fit_index` 是某个具体实体或聚合单元针对一项明确市场任务的满足程度，取值为 0—100。它不是资源固有分、类别默认分或跨市场总分。

主结果仍是物理能力和准入状态；指数只作为便于展示和比较的辅助结果。

### 11.2 单项满足率

对“越大越有利”的任务要求：

```text
r_power   = min(P_available / P_required, 1)
r_energy  = min(E_available / E_required, 1)
r_ramp    = min(R_available / R_required, 1)
r_duration= min(D_available / D_required, 1)
```

对“越小越有利”的任务要求：

```text
r_response = 1                         , T_actual <= T_limit
             T_limit / T_actual        , T_actual >  T_limit

r_tracking = 1                         , error_actual <= error_limit
             error_limit/error_actual  , error_actual >  error_limit
```

所有比值限制在 `[0,1]`。达到任务要求即记为 1，超过要求的能力保留为物理裕度，不通过额外加分扭曲任务满足含义。

只计算该市场和该任务真正适用的指标。某项指标没有规则、标准、任务要求或可核验锚点时，不自行生成阈值。

### 11.3 最短板指数

设本任务有可核验要求的关键指标集合为 `K_required`：

```text
scenario_fit_index = 100 × min(r_k),  k ∈ K_required
```

该式不需要人工权重，且能直接指出最薄弱的履约条件。输出同时列明：

- `bottleneck_metric`；
- `bottleneck_value`；
- `required_value`；
- `capability_margin`；
- 其他单项满足率。

### 11.4 何时不计算指数

以下情况输出 `not_computable`，而不是强行给分或显示为 `0 分`：

- 没有明确市场任务或正式测试场景；
- 关键任务要求没有可核验阈值；
- 关键实体参数缺失；
- 输入对象和规则适用对象不匹配；
- 只有跨场景、跨设备的单一案例，无法合理迁移。

类别层通常输出证据化能力区间；只有类别条件和评价任务都明确时，才输出带区间的场景适配结果。

### 11.5 区间传播

当能力输入为 `[lower, upper]` 时，各单项满足率和最终指数也输出区间：

```text
scenario_fit_index ∈ [score_lower, score_upper]
```

区间较宽说明信息不足，不应通过取中值伪装成精确结论。

## 12. 六项结果的专属计算

### 12.1 现货

- 任务输入：方向、分时功率/电量曲线、持续时间、允许偏差和适用申报条件；
- 能力输入：预测区间、可用功率/电量、爬坡、持续、基线和恢复；
- 主结果：分时可信可申报量、场景适配指数、偏差风险和瓶颈；
- 规则门控：按主体类型匹配注册、计量、最小变化量和储能持续时间等条款。

### 12.2 调频

- 任务输入：上/下方向、调频容量、响应限制、调节速率、跟踪误差和持续时间；
- 能力输入：端到端响应、双向容量、爬坡、跟踪、SOC/工艺状态和控制能力；
- 主结果：可信调频容量、场景适配指数、性能瓶颈；
- 规则门控：可观、可测、可调、可控，以及适用的 AGC/直接控制和性能测试条件。

### 12.3 备用

- 任务输入：预留方向、容量、启动和达到目标时间、持续时间及恢复要求；
- 能力输入：可信预留容量、响应、持续、可用率和再调用能力；
- 当前结果：物理备用能力、模拟/研究任务下的准备度指数和缺失条件；
- 当前门控：山东为 `not_open`。没有山东正式阈值时，必须把任务标为正式测试、论文案例或模拟假设，不能冒充现行市场门槛。

### 12.4 爬坡

- 任务输入：上/下方向、所需爬坡容量、爬坡率、启动和持续时间；
- 能力输入：上/下爬坡率、可用容量、方向切换、控制、恢复和历史性能；
- 主结果：可信上/下爬坡能力、场景适配指数和瓶颈；
- 规则门控：适用主体、控制、数据、申报和性能条件。

### 12.5 绿电供给侧

- 任务输入：合格绿色项目、合同电量/曲线、交易时段、用户关联和追溯要求；
- 能力输入：合格绿色电量预测、项目映射、上网/自用分计量和合同履约信息；
- 主结果：可履约绿色电量、交易履约状态、供给侧适配结果和证据；
- 结算关系：绿色环境价值结算量按现行规则受合同电量、合格发电侧上网电量和用户侧实际用电量共同约束。

### 12.6 绿电消费侧

消费侧保持一个顶层结果、两个子维度：

1. `transaction_compliance`：根据用户、合同、实际用电、交易方向和绿证追溯判断交易履约适配；
2. `absorption_synergy`：在明确移时任务下，根据可转移负荷、电量、时段匹配、持续和恢复计算消纳协同。

`absorption_synergy` 只表示物理移时能力，不直接形成市场准入、绿色环境价值或收益。两个子维度分列展示，不进行无依据的加权合成。

## 13. 步骤 S8：单市场能力与多市场同时可行域

### 13.1 单市场独立能力

对每个市场分别假设其他市场未占用资源，计算：

```text
standalone_capability(m) = 仅服务市场 m 时的最大可信能力
```

该结果用于回答“这个资源单独面向某市场时最多能做什么”，不能把六个独立最大值同时承诺出去。

### 13.2 多市场同时参与

为资源 `i`、市场 `m`、时段 `t` 定义容量或功率分配变量 `P(i,m,t)`。至少满足：

```text
Σ_m p_up_allocated(i,m,t)   <= p_up_available(i,t)
Σ_m p_down_allocated(i,m,t) <= p_down_available(i,t)
```

并同时考虑：

- 充放电、增减负荷和购售方向互斥；
- 跨时段 SOC、热量、库存、车辆需求和生产任务守恒；
- 响应、爬坡、持续和恢复条件；
- 聚合控制、站级和网络上限；
- 已签合同、已中标容量和安全裕度；
- 绿色电量、用户电量和绿证不得重复归属。

算法首先输出 `multi_market_feasible_set`，即能够同时履约的组合范围。没有明确业务目标、市场任务或价格时，不凭人工权重选出唯一“最优组合”。

如果已有真实合同和调度任务，则以全部任务可履约为约束检查可行性；如果需要经济优化，则进入独立的经济模块，以可核验净收益为目标选择组合。

## 14. 步骤 S9：经济结果独立计算

技术适配指数不包含市场价格、收入或成本。经济模块只在技术可行域内运行：

```text
expected_net_value
= rule_based_revenue
- activation_cost
- energy_cost
- degradation_cost
- production_or_comfort_cost
- opportunity_cost
- expected_deviation_or_penalty_cost
```

要求：

- 收益和费用计算必须对应现行结算规则；
- 价格使用带日期的实际数据或明确情景，不使用永久常数；
- 无法量化的成本单列，不填零；
- 山东备用正式开市前不计算确定性备用市场收益；
- 经济结果不反向修改设备的技术适配指数。

## 15. 数据完整度与证据输出

### 15.1 数据完整度

对当前市场任务实际需要的字段集合 `F_required`：

```text
data_completeness
= 已取得可核验证据的必需字段数
/ 必需字段总数
× 100%
```

该指标只表示必需数据覆盖情况，不代表数据质量、适配能力或履约概率。必需字段由市场规则、任务和资源专属约束共同确定，不由人工随意增减。

### 15.2 证据质量

每个字段分别保存：

- 数据来源和原始记录；
- 适用实体、设备亚类和工况；
- 采样周期和时间范围；
- 证据等级；
- 缺失、异常和过期状态；
- 是否进入正式计算。

不再用一个主观“置信度”系数乘到分数上。需要表达不确定性时，优先输出能力区间、适配指数区间和缺失项。

## 16. 示例输出格式

```text
对象：某储能聚合单元
市场任务：上调 1 MW，持续 30 min，要求 60 s 内达到目标
场景来源：模拟任务（仅用于算法演示）

市场状态：operational
准入状态：pending_evidence
可信物理能力：0.8—1.2 MW，0.55—0.72 MWh
响应时间：40—55 s
场景适配指数：暂不可形成正式入市分；物理能力试算区间 80—100
最短板：上调功率下界
数据完整度：8/10 = 80%
缺失项：正式性能测试、部分聚合控制记录
经济结果：未计算
```

该示例展示算法输出结构，不代表任何真实项目或山东市场结论。

## 17. 第一版最小可运行方案

1. 选择一个具体资源实体或明确的模拟实体；
2. 选择一个有正式规则阈值或明确假设的市场任务；
3. 按资源专属约束计算带上下界的能力；
4. 执行市场状态和聚合准入门控；
5. 逐项计算任务满足率与最短板指数；
6. 输出物理能力、指数、瓶颈、缺失项和数据完整度；
7. 分别计算单市场独立能力；
8. 再加入第二项市场任务，验证容量互斥和跨时段约束；
9. 技术可行后，使用带日期的价格情景单独演示经济结果；
10. 对参数上下界做扰动，检查短板和结果变化是否符合物理规律。

## 18. 验证方案

### 18.1 规则一致性

- 门控结果是否与适用规则条款一致；
- 规则更新后是否能够通过配置表更新；
- 备用 `not_open` 是否阻止正式准入和收益输出；
- 绿电供给、交易履约和消纳协同是否保持边界。

### 18.2 物理一致性

- 增加可用功率不应降低同任务适配指数；
- 延长响应时间不应提高快速服务适配指数；
- SOC、温度或库存趋近安全边界时，可用能力不应增加；
- 同一容量不能在多个市场同时重复使用；
- 调用后恢复和反弹应影响后续时段能力。

### 18.3 可解释性

- 每个结果可定位到资源参数、市场要求和公式；
- 最短板与单项满足率一致；
- 缺失关键字段时不生成伪精确分数；
- 类别资料替换为实体实测后，来源和结果变化可追溯。

### 18.4 后续真实数据验证

- 使用真实市场任务、响应曲线和结算记录检验可申报能力与实际履约差异；
- 明确训练、校准和测试时间段；
- 与简单加权、TOPSIS、灰色关联等方法进行对比；
- 确定“模型精度不低于 90%”具体评价对象和指标后再开展验收，不提前声称已经达到。

## 19. 专利可凝练的技术链

候选技术链为：

```text
规则版本识别
→ 异质资源专属状态建模
→ 带不确定区间的实体能力域计算
→ 聚合约束和可信能力形成
→ 市场运行状态与准入门控
→ 面向明确任务的最短板适配指数
→ 单市场独立能力与多市场同时可行域
→ 瓶颈、证据和改进路径输出
```

专利创新性不能仅建立在“打一个分”上，应进一步突出：

- 类别证据化范围与具体实体参数的可追溯切换；
- 资源专属约束向统一能力域的转换；
- 规则门控与物理能力分离；
- 区间输入和短板结果传播；
- 多市场容量互斥及跨时段恢复约束；
- 新资源和新规则的可扩展接入。
