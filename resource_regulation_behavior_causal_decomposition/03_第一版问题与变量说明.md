# 第一版问题与变量说明

## 1. 第一版研究问题

在同一类市场调节任务中，**市场激励和任务要求**与资源的**实际响应完成比例**有什么定量关系？这种关系是否会因资源初始状态而改变？

本版本研究的是一次任务能否被较好完成，不同时承担可调容量预测、用户长期意愿建模和资源智能分类等后续任务。

## 2. 结果指标：实际响应完成比例

### 通俗解释

一次任务要求资源调节 100 千瓦，资源实际完成了 80 千瓦，则完成比例约为 80%。这个指标越高，说明资源越能按要求执行调节任务。

### 建议计算口径

优先使用系统已经记录的“完成比例”。若没有，可按下列原则计算：

```text
实际响应完成比例 = 有效实际调节量 ÷ 要求调节量
```

- 要求调节量来自调节指令中的目标功率或目标曲线；
- 有效实际调节量来自实际功率相对基线的变化；
- 上调、下调分别按同一方向计算；反方向响应不计为完成；
- 比例原则上限制在 0 至 100% 之间，超过目标的部分在第一版中按 100% 计；
- 对目标曲线任务，可按整个任务窗口的累计调节量计算，而不是只看某一个时刻。

这是一项**待真实数据核对后确认的口径**。若系统已存在成熟的考核口径，优先采用其口径，并记录计算规则。

## 3. 第一版重点因素

### 重点因素 A：市场激励

例如补偿标准、价格信号或奖励强度。要回答的是：在其他条件大体相当时，更高的激励是否对应更高的完成比例。

### 重点因素 B：任务要求

先只选择两个容易理解、且通常能从指令中获取的因素：

1. 要求调节量；
2. 要求持续时间。

它们用于判断“任务本身是否更难完成”，避免把任务难度误判为资源能力差。

## 4. 必要控制条件（不是越多越好）

| 条件 | 为什么需要 | 第一版是否必需 |
| --- | --- | --- |
| 资源额定能力或历史常见可调水平 | 100 千瓦对不同资源的难度不同 | 是 |
| 任务开始前的资源状态 | 资源在不同初始工况下可响应空间不同 | 是，按资源类型选一个关键状态 |
| 时间/场景标记 | 白天夜间、工作日/节假日或不同市场场景可能不同 | 是 |
| 天气、用户偏好、绿色属性等 | 某些资源或场景可能重要 | 暂不默认加入；有明确业务理由再加入 |

## 5. 第一版关系图

```text
市场激励 ─────────────────────────┐
任务要求（调节量、持续时间） ──────┼──> 实际响应完成比例
资源初始状态 ─────────────────────┤
资源额定能力/个体差异 ─────────────┘
时间或市场场景 ────────────────────┘
```

图中的前两项是希望重点量化的因素；其余项用于保证比较公平。以后如研究“激励是否通过用户接受影响执行”，再单独加入用户接受这一中间环节，避免第一版过早复杂化。

## 6. 数据到位后先做的检查

在建模前，先检查是否至少具备：

1. 能把一条指令和一条执行结果对应起来的任务编号；
2. 资源或资源组编号；
3. 任务目标、任务时间和实际响应结果；
4. 一个市场激励字段；若没有，第一版改为研究任务要求对完成比例的影响；
5. 一个资源能力或初始状态字段。

如果以上关键项不完整，不强行建模；先调整研究问题或与对接方确认可替代数据。
